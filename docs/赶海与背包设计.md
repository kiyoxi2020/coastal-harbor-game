# 赶海与背包：下一版设计

状态：方向已确认，细则待用户审阅；尚未实现。基线为当前v0.3.1。

## 目标与范围

让玩家从潮汐台阶走下沙滩，拾取海产并看到背包数量变化。本阶段只验证拾取手感与探索动机，不宣称已经实现10–15分钟完整经营循环。

沿用现有640×416画面、海盐像素风、人物和建筑。只扩展潮汐台阶附近一块连通沙滩，不增加新地图。相比先做种植或继续纯美术打磨，赶海优先复用现有海岸与市集主题。

## 玩法与输入

- 固定低潮，无时间压力；本阶段不做每日潮汐时段、睡觉或资源刷新。
- 蛤蜊、海螺、海带三种物品，各放置两个固定拾取点，共六个；每个点提供一个物品。固定布局便于测试，不先做随机生成。
- 保持WASD/方向键移动。距离物品中心不超过24个逻辑像素时显示名称与E拾取提示，物品与玩家必须处于同一可达沙滩区域，不允许隔海或隔障碍拾取。
- 多个拾取物在范围内时只选择最近一个，同距离按固定物品点编号排序；提示与实际目标一致。
- 一次E按下只完成一个动作，长按不连续拾取。有提示窗口时E只关闭窗口，本次按键不得同时拾取或打开另一个窗口；必须释放后再次按下。
- 无窗口时，可拾取物优先于原有地点查看。没有物品时维持原来的地点查看交互。
- R只返回路口并关闭提示，不清空背包、不恢复已拾取物。

## 背包与反馈

采用三个固定物品计数栏，不做格子拖拽、容量限制、丢弃或背包快捷键。数量初始为零，只接受已登记物品的正整数增量。以独立数据对象保存数量，HUD只负责展示。

拾取成功后先更新背包状态、标记拾取点已领取，再隐藏场景物品并显示短暂“蛤蜊 +1”等非模态提示。重复领取同一编号必须无效；无效物品不得让场景资源消失。三个计数栏常驻，避开底部地点弹窗，不遮住台阶出口和拾取点。

拿完六个物品后显示“今日赶海收获已集齐；市集交易将在后续版本开放”。退出重开重置这一轮，并在开场说明“本版暂不保存进度”。现有海鲜摊仍为查看，不显示可出售的误导提示。

## 场景与美术边界

沙滩使用清楚的干沙、湿沙、水线分界；只修改台阶周边地形、水面绘制和对应碰撞，不能仅移除海面碰撞而让玩家走在水上。六个点不能放在台阶狭窄出口、HUD覆盖区或障碍内。保留其余海域不可通行、码头通路和原有树木遮挡关系。

三个物品使用简洁、可辨识的小型像素图形和接地阴影，最近目标添加轻量高亮。不重新生成整张场景、不更换已确认树木风格。本阶段不依赖新增生图任务。

## 实现职责

- 地图数据：沙滩范围、碰撞与固定拾取点编号/位置/物品类型。
- 背包状态：有效物品校验、数量与变更通知，不依赖HUD。
- 拾取控制：目标筛选、已领取编号、一次按键的原子领取流程。
- 场景入口：连接拾取、现有地点查看与R回路口，统一输入优先级。
- HUD：三个计数、当前动作提示与短暂收获反馈；保留E关闭规则。

只为本阶段增加必要模块，不改造整个项目架构。以后交易直接消费背包数据，不从界面文字读取库存。

## 验收

1. 自动测试：三种初始数量为零；有效拾取加一；重复编号、无效类型及非正增量不改变库存；长按和窗口关闭不触发额外拾取。
2. 集成测试：提示与目标一致；六点全部领取后各为二，总计六；R保留状态；重新启动恢复初始演示状态。
3. 路线验证：出生点能经台阶到达全部拾取点并返回；不能进入外围海面或穿过旧建筑；原有地点仍可查看。
4. 回归：运行现有交互、世界、树木、环境四组测试；因新增可通行沙滩而调整旧海面断言时，明确记录修改原因，不直接删掉边界检查。
5. 画面试玩：按原始逻辑分辨率和整数放大检查沙滩边界、物品辨识度、人物遮挡、HUD与中文文本；自动测试不代替人工画面检查。
6. 发布：验证完成后更新当前2D交付及源码包，历史包移入Git忽略的本地归档；不在最新交付里堆版本，不改动3D。

## 后续边界

交易与金币、旧屋修复、次日刷新与存档分别在后续阶段实施，本次均不包含。当前发布试玩保持不变，设计审阅通过后再写实施计划、编码和验证。
