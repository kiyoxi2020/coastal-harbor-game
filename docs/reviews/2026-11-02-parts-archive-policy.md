# 人物最终归档目录规则统一

用户要求将人物相关最终归档位于parts的要求写入设计文档，处理矛盾并约束后续开发。本轮仅修改规范、导航与交接文档，未改图片、注册、配方、构建、运行或冻结基线。

## 统一后的规则

唯一制作规范 `docs/design/character-art-pipeline.md` 第8节明确：人物相关最终美术实际PNG/图集及必要布局、映射、mask、manifest统一归入 `art/characters/parts/`；只在parts放清单引用外部图片不算完成。母版采用parts/body/<body-id>/<revision>，其他部位沿现有款式/体型/动作适配路径，不创建第二套目录体系。

sources保留原始生成证据与制作中间派生，templates保留身份/姿态/canonical注册参考，builds保留严格烘焙制品；这些技术依赖不能替代parts最终美术包，也不为了整理而盲移、删除或覆盖已冻结数据。新路径须记录像素/时序/注册等价，验收资格不能由目录位置推导。

## 矛盾与处理

| 原表述/风险 | 处理 |
|---|---|
| templates保存“所选母版”，易被当作最终图片目录 | 明确其身份/定义/canonical技术职责，最终图片入口为parts |
| pack输出可放parts或sources/derived，未区分用途 | 工具能力保持；文档限定derived为制作中间产物，最终输出选parts |
| builds为正式留存产物，易与最终美术归档混同 | 保留严格构建合同，明确不能替代parts图片包 |
| 旧换装设计将运行v2灰衣当作当前制作母版 | 区分运行v2与制作v4，改用当前parts母版和归档；旧衣物认可不继承 |
| 开发计划6处退役人物路径仍是可点击入口 | 标为明确历史路径，不恢复旧目录，也不伪改历史结果 |
| 仅靠check通过便宣称归档完成 | AGENTS新增强制目录要求；规范增加实际文件、适用verify、等价及引用同步的交付检查；说明现有静态check不覆盖全部目录语义 |

同步文件：AGENTS.md、唯一制作规范、人物库README/CURRENT、adult-v4 README、工具README、Godot开发README、body与换装设计、开发计划，以及PROJECT_STATE/HANDOFF交接。历史回执、归档JSON和不可变生成输入未改写。
