# 统一人体、动画与衣物组合制作规范

版本：2.1，2026-10-28（仅更新资源存储与留存约定；制作合同保持版本2）。按用户本轮要求，将动态人体与衣物组合正式纳入唯一制作规范；本文件替代原先“先扩完整静态库、最后另做动画”的执行顺序。AGENTS和各复盘页引用本文件，复盘不维护另一套制作合同。当前四向动作与代表性组合已有分范围认可；实际覆盖见人物库 coverage.json，不等于完整组合或正式生产迁移完成。

## 1. 目标、母版与适用范围

所有主角、NPC、成年男女、老人和儿童，采用**同一体型的动作模板＋可复用部件视图＋衣物覆盖规则＋姿态前后关系**构造。稳定衣身可以跨帧复用，袖子、裤腿、鞋等按实际形态切换；有限角色配方先离线合成完整动画交付。

正式交付只保留一套现行人体模型体系与播放/合成管线，不长期并行维护旧版和新版。成年男女、老人、儿童是该体系内的体型变体，仍保留各自比例及适配；“一版”不意味着全员使用同一个成人轮廓。新增动作和样式通过同一资源合同扩展，不重新建立一套人物生成或播放系统。

现行成年标准制作母版由[人物库catalog](../../art/characters/catalog.json)的`selected_template`与`body_source_archive`唯一指定。2026-11-02按用户要求切换为Q27=A认可的`adult-standard-v4`男性背心短裤，完整源/注册/108身体姿态及56农事工具表现见[归档](../../art/characters/parts/body/adult-v4/archive-r002.json)。后续穿戴读取该模板active_revision及同姿态body-reference，旧衣物/mask不自动兼容。更早原始source.png、v1眉毛修订、v2灰色长袖长裤与v3独立idle保留历史来源/冻结依赖，不覆盖像素，也不再作为新制作的默认母版。此选择不等于默认游戏切换、严格物理接触或完整动态换装发布。

保留该人物自身的脸、头颅、耳、身体比例与身份特征；运动时允许自然改变姿态和投影，不把站立脸手像素硬贴到转头、抬手或弯腰帧。旧A/B等认可图仅是Git `379a9bc` 中的 `art/design/character-bodies/README.md` 历史参考，不能拆其脸手补到新人物。

每个体型使用独立template_id/version，动作集用motion_set_id/version，姿态用pose_id；一个姿态不再被误称为一个独立体型。女性、老人、儿童各自冻结比例，不将成人缩小当儿童；性别不作服装硬限制，兼容取决于实际体型与姿态。

用户已明确新版动作覆盖度须与旧版一致：所有声明为完整新版动态角色的配方必须支持walk/run/hoe/water/harvest五类动作，各含south/west/east/north四方向，另有四向idle及动作衔接。阶段3四帧walk只是局部技术验证，不降低最终覆盖。旧版每向六帧共120帧是参考，不要求新版机械保持相同绘制帧数，但动作完整性、可读性与游戏响应不得倒退。拾物及其他职业动作按实际行为另加，不能用站姿滑动或加速walk冒充缺失动作。本轮六类各10候选目标保留为外观目录任务，不等于十体型×所有衣物均已运动适配。

## 2. 唯一制作顺序与阶段出口

| 阶段 | 必须交付与验证 | 出口限制 |
|---|---|---|
| 1 外观冻结与整帧登记 | 选定完整四向母版，保留GPT源图/提示词/哈希；登记画布、根点、真实关节与显示尺度，检查alpha | 身体比例未确认不能开始该体型的穿戴适配 |
| 2 静态接口基线 | 四向无发无帽/发/帽/发帽共16状态；一套衣裤鞋及第二套逐槽替换，检查脸、袖腕、腰、踝鞋 | 已通过的同版本证据可复用；此阶段只证明静态接口 |
| 3 单侧四帧运动验证 | body01西向walk四帧；一件无袖/短袖A与一件长袖B，共用裤鞋与固定头部；衣身复用、袖子换帧、覆盖及前后关系实际合成 | 先验证真实动作和衣体接口，再增加运动资源款数 |
| 4 四向完整动作模板 | idle/walk/run/hoe/water/harvest及必要隐藏身体；两套衣裤鞋A/B；同一固定发型，分别无帽/一顶帽子 | 动作、脚点、握点与层序成立后才能声称运动兼容 |
| 5 动态混搭与原生验收 | A/B上衣×下装×鞋的8种配方，每种均验证无帽/有帽、四向全部动作及切换；离线合成与原生连续播放 | 只发布实际验证的配方；混搭数量和验收范围不得偷换 |
| 6 生产接入与扩展 | 全部需迁移角色的配方覆盖五类四向且验收后统一接入；新体型重复1–5，再为入选衣物增加适配 | 新体型、新动作和新款不自动继承兼容性，保留独立证据 |

四帧是阶段3的具体试验约束，不是所有动作的统一帧数。若循环缺少必要姿态或四帧仍不合格，记录失败原因，增加经评审的关键帧或调整节拍；不得为了保住四帧数量降低动作质量。站立候选可继续整理，但不能绕过3–5直接批量登记为动态成品。

每一阶段先完成具体可审查小样再判断外观；selected、用户视觉认可与自动检查分别记录，不重复索取泛泛方案确认。同一方法两次出现同类错误后，先分析源图/姿态/分层证据，再决定修法。

## 3. 坐标、锚点与合法运动

源图保留原分辨率、nearest显示，不预压成世界逻辑像素再放大。现站立每向512×768、四向2048×768是现有源稿规格；运动如需更大范围，统一扩大该动作集画布并重新登记，不裁掉举臂或工具，也不单独缩小某帧。整帧裁切和场景统一缩放保留元数据，四方向保持统一像素密度。

坐标以画布左上为(0,0)，x向右、y向下，单位为源图像素。人物世界根点为稳定的脚部占地参考点，不取当前图像外框中心，也不随帽子、举手或工具变大移动。脚底接触点可以随步态变化，必须与根点区分。

记录颈根、肩、肘、腕、腰、髋、膝、踝、脚与工具握点的实际位置；不按总高百分比猜接口。左右手脚按角色自身解剖命名，近/远侧由direction/pose映射，左右转身不自动镜像替代未经验证的非对称服装或持物。

允许的部件位置变化来自已冻结动作模板的锚点轨迹及部件注册偏移，所有换装服从同一姿态。**禁止的是为修错位随意挪动脸手脚、单独缩放衣鞋或拉长腿；正常动作驱动的位置变化合法。**

初版部件只有两种定位方式：full_frame视图已处于当前姿态坐标，placement为零；anchor_local视图登记自身pivot、所属锚点和固定偏移，位置由当前姿态锚点减pivot得到，不再次叠加整帧位移。初版只使用整数像素平移、经批准的局部视图替换和整帧统一显示缩放；需要旋转/弯曲的投影由对应视图表达。骨骼/网格任意变形不作为本版默认实现。

## 4. 部件源图、姿态映射、覆盖关系分别保存

### 完整部件源图

一个设计可以包含衣身、左/右袖、前后衣摆，或左/右裤腿、左右鞋、前后发、帽檐等子层。按实际遮挡需要拆分，不机械把每个人都拆成相同数量。内部子层、方向、动作视图、换色和体型适配均不增加独立设计数量。

源部件保留声明动作与组合会露出的隐藏区。手臂盖在衣身前产生的缺口不永久裁入通用衣身；站立源稿没有画出的部分仍须GPT在同母版条件下补画，mask不能恢复不存在的像素。隐藏身体也只补目标动作与服装会露出的肩腋、腿踝等部位，不先制造无用解剖库。

GPT负责新美术与修补像素；脚本负责登记、提取、mask、合法放置、合成、打包与检查。颜色/连通域只能辅助定位，不能独自决定正式归属。眉鼻耳线属于身体，不能因颜色近似而进入发帽层。生成漂移或混入另一张脸手时退回源稿。

### 姿态到视图的多对一映射

每个动作帧必须有完整映射，映射可以复用同一画面；不要求每个姿态独立生图，也不要求一帧一个PNG文件。

| 四帧西向walk示例 | 衣身view_id | 袖子/手臂view_id | 遮挡 |
|---|---|---|---|
| 0 | torso_w_A | 当前姿态所需视图 | pose_0的覆盖及层序 |
| 1 | torso_w_A | 当前姿态所需视图 | pose_1的覆盖及层序 |
| 2 | torso_w_A | 当前姿态所需视图 | pose_2的覆盖及层序 |
| 3 | torso_w_A | 当前姿态所需视图 | pose_3的覆盖及层序 |

表中复用仅在衣身形状与投影一致时成立，实际袖子视图数量由动作决定。弯腰、扭转、领口或衣摆改变时使用B/C等新视图；裤腿和鞋必须跟随各自腿脚，不能借上衣复用把鞋固定在站姿。纹理视图数量、时间轴帧数、图集文件数分开统计。

### 三类mask与层序

| 信息 | 回答的问题 | 作用范围 |
|---|---|---|
| source_ownership | 当前GPT源图哪些像素属于这个部件？ | 仅用于该源图/姿态提取，不能从站姿直接推广到抬手帧 |
| coverage | 当前服装覆盖身体的哪些表面？ | 指定目标身体子层/区域、姿态和衣物版型；长袖与背心不同 |
| occlusion | 当前谁在谁前面？ | 优先用有序子层和alpha；局部交叉时拆子层或登记真实遮挡mask |

同一屏幕坐标可以叠放多个完整表面，最终可见归属由当前层序决定；“像素归属明确”不再表示所有部件在源图中必须互斥或永久挖空。透明边缘不得重复叠加同一脸线造成加深。

coverage作用于指定的被覆盖表面，不能把衣身屏幕矩形内的全部皮肤都删掉：摆到胸前的手掌仍应显示。手臂在后时由衣身遮住，在前时按当前袖长显示袖子与裸露手部。人体轮廓、肤色、图片alpha都不能独自确定这两个关系。

同体型、同动作、同版型的衣物可引用同一coverage_profile；领口/袖长/衣摆有差异时需独立覆盖轮廓或登记差异，不能默认同为“上衣”就通用。衣物间也要明确目标表面，例如裤脚塞靴、帽下收发、上衣塞裤：使用已验收的组合变体或声明不兼容，不能任意擦掉突出部分。

mask与目标表面必须在同一姿态坐标系，记录source/pose/owner/target及哈希；二值或带alpha边缘以实际轮廓为准，合成不能把边缘alpha重复相乘。无必要时直接用图层覆盖，不为所有部位额外画mask。源素材保留完整，遮挡结果写入派生预览或烘焙帧。

## 5. 资源合同与合成流程

以下为待实现的数据合同，字段是设计要求，不表示运行时已存在相应文件。所有引用使用项目相对路径/稳定ID与内容哈希，缺项直接报错。

| 资源 | 必要字段及含义 |
|---|---|
| 体型 | schema_version、template_id/version、selected_source_hash、canvas_px、root_anchor_px、display_scale、landmark定义、左右命名 |
| 动作集 | motion_set_id/version、template版本、actions；各action以稳定action_id/action_version登记directions、loop、frames（有序pose_id＋duration_ms正整数）、events、允许的切换策略、所需anchors/slots、move_policy及event_handler_id |
| 姿态 | pose_id、action/direction、body_views、landmarks_px、foot_contacts（left/right及点位或airborne）、grip_points、默认层序、所需隐藏区 |
| 部件视图 | design_id、variant_id、part_id、view_id、texture/atlas_region、placement_mode、pivot/anchor/offset、来源/提示词/哈希；body模板与动作集版本 |
| 衣物动作映射 | 每个支持pose_id的view引用、子层可见性、coverage_profile、必要层序修订；复用同view不省略姿态映射 |
| 覆盖与遮挡 | pose_id或明确姿态集合、owner_part、target_part、mask引用及坐标系；归属/覆盖/遮挡用途、兼容条件和轮廓依据 |
| 角色配方 | recipe_id/version、体型/动作集版本、slots映射（基线hair/top/pants/shoes/hat，可由槽位定义扩展）及各设计变体、required_actions、allowed_combinations、工具类型、已验证范围 |
| 导出与证据 | 输入artifact_digest、合成规则/工具版本、纹理索引、动作时长、根点/接触事件、自动检查/停帧/录像/用户认可及其覆盖范围 |

每个姿态按以下顺序合成：

1. 解析配方和动作能力，检查体型/动作集版本、视图、隐藏区及组合依赖齐全；不支持时拒绝导出或加载，不借另一个身体自动补帧。
2. 从唯一动作时间确定pose_id，解析全部部件的视图与合法placement；身体脸手也使用这一姿态，禁止混入站姿旧脸。
3. 在各自目标表面上应用已声明coverage，按此姿态由后至前的有序列表组合身体、衣物、发帽和工具；局部交叉需要明确拆层，不能出现无法排序的循环依赖。
4. 生成预览或烘焙完整帧，保留统一画布和根点元数据；同像素结果可去重存储，动作索引与事件时序仍独立保留。

原装拆层重建需与批准的完整穿戴参照逐RGBA核对，差异有明确允许区域与原因。这只证明重建，8种混搭和连续动作另验。静态“非编辑区不变”只比较同一pose换装前后；不同动作帧改姿态是正常变化，不能要求其脸手坐标或像素恒等。

## 6. 播放、交互与世界关系

首版生产交付采用**制作侧分层组合、交付侧按有限配方离线烘焙完整动画**，复用现有单角色AnimatedSprite2D路径。评审工具必须支持逐槽组合、停帧和查看子层/mask；不同时建设完整角色编辑器或运行时自由衣柜。

每角色只有一份权威状态：action、direction、elapsed、playback_rate、action_instance_id。身体、衣物、工具均从它取得pose_id，不让各层独立play()后假设同步。未来实时分层仍遵循同一合同。

- idle/walk/run按移动状态选择；walk与run之间使用已登记的接触相位映射，无法映射的切换采用明确过渡姿态。急停进入稳定idle，转向更新所有层；不得留下旧方向衣鞋。
- 工具动作进入时固定动作方向并锁移动，完成后恢复idle；初版运动中不执行外观换装请求，延至idle整套原子替换。若某动作需要取消，显式定义退出姿态与事件处理。
- 脚点驱动世界位置/碰撞，动作纹理保留合理起伏；支撑脚随世界位移与摆腿协调，腾空姿态明确记录。禁止逐帧把两只鞋底都钉回同一y。
- 工具按真实握点贴手，必要时分柄的前后段及手指层。接触点必须落在合法目标范围；够不到时由玩法拒绝或移动到合法站位，不能拉长工具或挪手掩盖。
- 世界按角色稳定根点排序，内部前后关系单独合成。树、柜台、门过渡应对整个角色及工具一致生效；帽子/工具图像外框不扩大脚部碰撞。生产接入时必须验证世界遮挡，不把内部mask替代场景空间关系。
- 接触事件由权威时间轴按越过的时间区间发出，以action_instance_id＋event_id去重；循环事件另含loop_index。低帧率跨帧不能漏发；取消不补发未来事件，暂停不推进，结束只通知一次。重播建立新实例，评审拖动时间轴不执行玩法事务。

现生产农事流程先提交事务，再播放hoe/water/harvest。本版视觉接触事件只驱动声音/特效与验收，不重复扣除或收获；若将业务生效移至接触点，另立玩法、取消、存档与幂等改动。collect不等于现有harvest动画，需独立动作时明确新增。

### 唯一现行版本与旧资源退役

旧版`player-unified-v4`是目前已接入的完整穿衣逐帧资源；新版是统一可组合模型及其烘焙结果。两者复用玩法动作语义和角色控制入口，新版完成后统一替换旧版表现资源。正式运行不提供新旧模型选择开关，也不保留按角色选择旧模型的长期兼容分支。

| 阶段 | 执行规则 |
|---|---|
| 新版制作与评审期间 | 正式游戏仍用当前旧资源，新稿仅在独立评审目录运行；对照旧版动作覆盖、节奏、接触和可读性 |
| 切换前 | 列出所有引用旧人物模型的实际场景/角色，使用新版对应配方覆盖其需求；五类四向动作及idle、动作衔接和角色接入检查通过后，形成一个完整发布清单 |
| 正式切换 | 在完整构建/场景安全加载边界统一采用新发布清单；删除生产场景、配置和代码对旧模型的引用，发布包排除旧模型资源及试稿，不形成新旧人物体系混合运行的交付 |
| 切换后 | 只维护新版人体、衣物和动作合同；旧源图/提示词/制作记录放工程运行目录外的历史归档，仅供追溯恢复，不是可被运行时选择的第二套人物库 |

用`character_model_id`标识唯一体系，`active_release_id`标识当前唯一发布清单；清单关联各体型、动作、衣物及角色配方的确切版本。不同体型/款式可以有不同资源版本，但都属于同一个发布清单和同一套加载/播放规则。候选稿和历史修订不进入该清单；资源版本号仅用于来源、升级和证据追踪，不表示多套人体同时可选。

玩法和存档保持角色ID及语义动作，不持久化图集位置或新旧纹理帧号。必要的服装选择保存稳定design_id/variant_id；删除或更名须提供显式ID迁移并验证存档，不静默随机换装。旧行走动画north/south/west/east可由接入适配映射到walk方向，不为重命名改变玩法逻辑；迁移适配在切换完成后不能成为双轨播放分支。

禁止“新版走路＋旧版耕地”、旧脸手脚拼新身体或缺帧回退旧模型。必需动作缺失时拒绝新版发布，继续保留现有正式构建，待补齐后整体切换；若需恢复历史构建，则整体回退构建版本，不在同一发布包里维护两套模型。

切换保留角色世界位置、碰撞占地和业务状态，整套纹理/根点/时序/工具附着一致，不在农事动作中途切资源。对照旧版验证五类四向、速度/滑步、输入响应、工具握点/落点、门遮挡与碰撞；事务仍只提交一次。本轮只确定退役规则，尚未删除在用旧模型或执行切换。

## 7. 动态组合验收

| 检查 | 完成条件及证据 |
|---|---|
| 结构与来源 | 所需动作/方向/pose/view完整，时长为正、图集区域有效、根点/锚点/mask坐标合法；输入与规则哈希齐全；未知组合拒绝 |
| 身份与比例 | 四向外观承接选定母版，儿童不是成人缩小；各姿态无混脸手、重复眉鼻耳线、异常头身变化 |
| 完整源与覆盖 | 脱去前景层后检查目标动作会露出的隐藏区域；每个mask有指定表面和姿态依据；胸前手不误删，袖内皮肤不漏，源衣身不留永久手掌洞 |
| 衣体与部件接口 | 全部声明配方逐帧看领肩/袖腕、腰髋、膝、踝鞋、发帽与握点，无断口、双肢、旧内搭、穿模和重复边缘 |
| 动态层序 | 手臂前后摆、双腿交替、举锄与落锄、转向时前后关系正确；交叉处拆层完整，无单个固定z误盖全身 |
| 连续动作 | 游戏实际尺度、明暗背景，walk/run至少各10循环并录制；急停/转向/工具开始结束、循环首尾不跳变、不闪衣鞋 |
| 接触与移动 | 支撑脚轨迹及工具握点相对批准姿态的最终屏幕误差目标≤1像素；按实际移动速度检查滑步；脚接触、腾空、工具落点分别记录，不能只看原地播放 |
| 时序与原子性 | 常规/低帧率跨帧、暂停恢复、变速、允许取消与重播，部件同相位，事件不重不漏，idle换装无半套更新 |
| 原生世界与交互 | 同尺度对照母版/主角，经过树/柜台/门、转向与使用工具验证真实遮挡和碰撞；测试档只在/private/tmp/coastal-* |
| 版本与认可 | 按步骤/预期/实际/结果记录；纹理、mask、映射、时长、配方、合成器和场景的artifact_digest绑定证据；用户认可单独登记 |

≤1屏幕像素是首次小样的验收目标，若像素采样或风格确需调整，必须在相关验收前记录理由与新阈值，不能失败后悄悄放宽。静态截图不能证明步态，headless只能证明结构和逻辑。

结果分别记录selected、registered、geometry_checked、static_swap_checked、motion_checked、dynamic_swap_checked、native_checked、user_accepted及对应体型/动作/方向/配方范围；不是一个可互相推导的单线状态。失败标rework_required/rejected；输入改变时受影响证据标stale，复查前为unverified。旧swap_checked只按原静态范围解释。

## 8. 目录、迁移与成本

### 8.1 最终归档必须落在parts（强制）

**人物相关最终美术归档统一放在 `art/characters/parts/` 下，必须包含实际采用的图片数据及必要配套数据；仅在parts放archive清单，再指向sources/templates/builds中的图片，不算归档完成。** 此要求适用于母版、体型变体、头发、帽子、衣服、裤裙、鞋及后续人物部件。某资源可被工具生成到其他目录，不代表那里是最终归档位置。

- 完整人物母版：`parts/body/<body-id>/<revision>/`，保存实际PNG/图集、帧布局/姿态映射、画布/根点/时长/整帧注册及manifest；图集可放该revision的`atlases/`。外层版本化archive清单绑定最终包、原始来源、认可范围与SHA。当前实例为`parts/body/adult-v4/r001/atlases/`、同级`layout.json`/`manifest.json`和外层`archive-r002.json`。
- 其他部位：`parts/<category>/<design-id>/`，沿现有`<template-id>/<motion-set-id>/<revision>/`保存实际最终纹理、view/pose-map及必要ownership/coverage/occlusion mask与引用；复用视图按合同登记，不为凑目录任意挪缩图片，也不另设第二套parts体系。
- 新部件最终归档与交付必须通过parts内的真实文件定位。新制作的配方/映射应绑定对应最终部件；模板canonical参考等技术依赖仍按严格合同保留，不能为了改路径绕过构建校验。

parts中已有的版本化候选或静态适配仍按各自状态保留；**放在parts内不自动等于已认可、可动态组合或可发布**。这里约束最终归档的实际位置，不以目录位置替代原有验收门禁。

### 8.2 各目录职责与不可替代关系

| 目录 | 职责 | 与最终归档的关系 |
|---|---|---|
| `parts/` | 最终采用的人物美术及其完整部件/注册/映射/归档数据 | 唯一最终美术归档根，不能只存指向外部图片的清单 |
| `sources/<source-id>/` | 制作期间的原图/参考与派生；验收后仅保留现行构建必需的独立动画输入 | 过程总结为文字后可删除原稿/失败稿/生成记录；必需动画输入不能代替parts最终图片包 |
| `templates/<template-id>/` | 母版身份、active_revision、动作/pose定义、画布/根点/时序及合同所需canonical参考 | 定义与注册入口；其参考PNG不能作为“最终图片已归档parts”的替代品，完整穿衣参考也不等于隐藏身体 |
| `recipes/`、`builds/` | 有限组合配方、严格烘焙输出与验证清单 | 构建产物必须按统一构建合同保留，不作为最终人物美术归档根；需要最终采用的美术仍须归入parts |
| `reviews/`、`evidence/`、`docs/reviews/` | 评审配置、认可与实际验证证据 | 证明确切资源范围；截图/视频/回执不代替部件图片归档 |
| `migrations/` | 路径等价、保全与恢复记录 | 记录迁移，不另建一份庞大archive资源树 |

原始源图、必要canonical及不可变构建允许在各自目录保留，不能为消除重复而损坏依赖。旧目录属于历史技术依赖，不构成今后继续把最终美术留在parts之外的例外。新路径产生新manifest/digest，以逐RGBA、姿态/时序/注册等价记录关联原认可，不重写旧回执，不把目录迁移冒充新的视觉、接触或发布验收。

制作代码位于`tools/characters/`，隔离试玩位于`godot2d/dev/characters/`，测试位于`godot2d/tests/characters/`；不在美术批次下另建合成器或Godot工程。正式发布另按发布合同进入`godot2d/assets/characters/releases/<release-id>/`。当前默认主角的v4背心短裤本地接入与旧NPC运行状态以CURRENT及runtime-baseline为准；parts归档不自动切换运行资源或授予发布资格。

### 8.2.1 最终动画独立与制作过程精简

用户2026-11-02明确要求：只保存支撑动画的数据，制作过程总结为文字。人物最终版本必须独立包含完整图集、布局/画布、根点、pose映射、时序、必要mask/层序，以及现行严格配方/模板/动画输入/构建和SHA认可绑定。最终构建不得继续依赖旧版本目录、失败稿或生成历史；完整旧图集已被最终稿覆盖时，不因旧authoring_inputs仍有引用就无限保留过程资产，应迁出依赖并按新manifest/digest验证等价。

此要求作为后续人物归档的默认规则执行，不需要用户每轮再次要求清理。制作期间可临时保留GPT原稿/提示词/中间稿以完成修改；最终动画包独立并验证后，只归档上述动画必需数据，清理不再使用的原稿、试验图、生成记录、过程截图/录像/测量和旧版本归档，关键方法、取舍和验证范围仅总结为文字。无需为了可追溯性另做二进制备份或维持旧过程链。现有严格合同所需的prepared/source.json/canonical可作为最终动画数据保留，但必须绑定完整最终稿、无旧版本依赖。此款优先于下文迁移历史中“保留原图/失败参考/临时保全”的一般要求；冻结生产基线及其他仍在使用的资源不因此自动解冻。

当前示例为adult-v5/r012及sources/adult-v5-animation-r012：最终PNG字节、pose/区域/锚点/时序及严格帧输出等价，旧原生证据仅保留文字结论，不能冒充新闭包回执。只清理依赖不扩大原视觉认可或改变生产发布状态。

### 8.2.2 本地归档与Git纳管

用户明确要求后续只将主游戏实际调用的资源加入Git。parts归档、构建通过、外观认可或评审器可加载仅说明本地动画包的状态，不代表可提交。尚未被主游戏调用的最终候选，以及原稿、生成记录、失败稿和过程媒体均为本地暂存资源，不加入Git；动画必需但仅服务本地工具/评审的快照、canonical及构建数据同样按暂存管理。当前未接入主游戏的adult-v5即属此范围。

纳管范围按主游戏入口、场景/脚本/配置、动态加载和导出清单的实际运行依赖确定。源码、工具、测试和文字文档按正常开发需要管理；已提交代码或测试不得强制依赖未纳管的暂存资源，应使用现有已跟踪夹具、测试代码在临时目录生成的夹具或显式可选评审入口。严格管线的固定目录可以本地存在并被ignore；接入主游戏后仅按实际依赖收窄ignore、逐路径加入，不为追溯制作历史提交整套过程包。已跟踪文件与冻结基线不因本条自动删除或解除跟踪。

### 8.2.3 运行包校验与制作源重建

`godot_integration.py verify-runtime <manifest>`核对自包含主游戏接入包：完整动作方向、实际PNG与RGBA哈希、导入处理、共享几何/时长/loop、SpriteFrames精确内容、路径安全及资源文件集合。运行完整性由冻结基线和这些实际数据保证，不读取本地制作源或生成器文件；source_build/recipe/generator字段只保留历史身份，不宣称已验证其存在或重建。Finder .DS_Store不属于Godot运行资源，符号链接和额外游戏文件仍拒绝。

原`verify <manifest>`仍严格验证本地配方/build、制作源和运行包的等价，不因源缺失自动降级。制作、改图和重新接入须执行严格重建；普通运行包/CI完整性不强制依赖未纳管的art数据。check核对冻结运行包，并验证本地实际存在的全部严格配方/build。默认测试以临时夹具或已纳管运行资源为输入，不要求恢复历史制作库。

旧数据链明确获准退役时，按精确清单撤销相应旧构建/配方/integration及冻结记录，保留现行主角/NPC的运行SHA与绑定，单列必要元数据差异；不重采整份基线、不屏蔽验证器。只服务已退役数据的CI迁移/静态导入步骤一并退役，通用源码与独立夹具的合同测试保留。

### 8.3 归档完成检查

1. 检查parts内实际PNG/图集及必要mask/布局/映射/manifest是否齐全；“只有清单”“只有sources中的派生图”“只有模板参考或build输出”均判为未完成。
2. 运行适用的pack/build verify，检查源与最终图像RGBA、pose顺序、时长、根点、尺寸及SHA。迁移不改像素时记录等价；发生美术/时序/配置变化则按实际依赖重验。
3. 更新catalog现行选择/归档、CURRENT、部件README及相关配方/评审引用；用户交付链接指向parts下实际图片与归档。旧路径仅以明确历史或技术依赖保留，不能与现行入口并列为默认制作来源。
4. 完成人物必需门禁和任务要求的验证；记录已验证/未验证范围。现有静态check不自动证明所有目录约定，开发者必须显式完成以上检查，不能仅以check通过宣称归档完成。

工作区只归档最终游戏/动画必需数据。被最终稿误列为强制输入的失败参考或旧图集，应先迁出依赖并验证等价，再清理过程资料；不因旧引用存在永久保留原稿，也不要求复制临时保全/庞大archive树。Git历史本身不因工作区清理而改写；本地暂存与Git纳管边界按8.2.2执行。

原认可保留确切范围、最终图像/帧SHA和文字结论。新清单产生新digest，以迁移等价记录关联旧认可，不把旧原生receipt用于新合同。只有支撑当前动画合同的元数据保留；旧生成/过程JSON可总结为文字，不继续执行或依赖旧路径。后续改图/时序/层序则使受影响证据失效，沿新revision重新验收。

旧静态所有权mask、手颈保护框、裤脚列边界只服务原standing_0，不直接复制到新动作。制作期间尚在使用的源稿/外观ID/提示词可复用，站立透明层仅在实际相同投影中复用，缺失隐藏区按需补齐。原60项静态库已退役；历史body09男童比例问题仅作设计提醒，未来体型须重新验证，未解决比例不能冻结为动作母版。

成本分别统计：独立绘制视图、隐藏区补画、姿态映射/覆盖规则、实际组合审核数量。姿态数×部件数只是兼容检查规模，不能当作独立生图次数。若与旧版一样每向每动作六帧，五类四向动作共120姿态，另加四向idle为124；8衣裤鞋配方为992状态，再验证无帽/有帽两种头部条件，共1984合成状态，均非1984次独立生图。其他职业动作及体型另计；阶段3的四帧数不作为完整动作集的统一帧数。

旧失败批次、静态候选和迁移过程数据已按用户授权清退，现行不提供其资源入口。Git历史未改写，但不要求恢复历史制作库；重新采用任何旧设计须沿当前合同注册、构建和验收，历史静态任务不代表现有动态能力。

## 9. 新动作、新样式与体型的扩展合同

### 统一标识与能力清单

人体体型、衣物设计、视图、动作、配方使用稳定ID；schema_version表示文件结构，内容revision表示具体资源修订，两者分开。生产合成器/播放器读取清单，不把十款、A/B两配方、四帧或六帧写死。四帧walk工具仅是范围固定的试验工具，接生产前须改为按合同遍历动作、方向、配方和可变帧数，不能直接把小样限制扩成总管线。

五类四向动作加idle是所有完整角色的最低覆盖；新增动作注册后，由角色的required_actions决定还需哪些能力。新动作不能偷偷替代或删除基础动作。只有所用体型及全部可见部件支持所需动作/方向/姿态、相关组合已验收时，配方才可进入发布清单。

能力取所需参与部件的实际兼容交集。动作中无需显示的部件必须由姿态显式声明hidden，并检查隐藏后的身体区域，不能用“看不见”绕过缺资源报错。对缺资源输出具体recipe/action/direction/pose/part与原因，不套静态图或旧模型。

### 新增动作的制作与接入

1. 注册新action_id，定义用途、方向、循环/时长、进入/退出/中断条件、move_policy、所需锚点/工具及事件含义。基础四方向不删减；新增动作若只适合特定方向，明确声明并由行为调用校验。
2. 在同一已认可体型上制作完整动作母版，确定接触相位、关节轨迹和必要隐藏区；复用已有同投影视图，新增形态单独画，不改旧动作的姿态内容来凑新动作。
3. 对将执行该动作的角色配方，逐件补齐其衣物/发帽/工具的pose-map、coverage和层序；未声明执行该动作的配方不必立即扩画，但不能被分配该行为。
4. 配置可沿用的事件处理器；若新增行为语义，例如游泳、坐下或搬运，新增明确的玩法处理器和验收。配置能扩展动画素材，不承诺任意新玩法零代码；只有已登记处理器可接收动作事件。
5. 验证新动作的全部声明配方，以及它与既有动作的进入/退出、取消/事件/世界碰撞；已有基础动作的输出哈希未变可保留美术证据，共享播放器或姿态合同改动则重验受影响动作。

示例：增加挥手，只新增wave定义、体型挥手姿态及所需袖臂映射；衣身/裤鞋在投影一致时复用已有view。增加挥锄的另一种力度，可扩展hoe视图或登记新语义动作，但不得通过文件名猜事件时机。

### 新增样式的适配

1. 登记design_id、占用slots、目标体型与动作模板、版型覆盖profile及互斥/依赖条件。设计ID不因动作或体型适配而增加。
2. 同版型的新配色/材质可复用经验证的形态和覆盖定义，但正式美术仍遵循GPT来源约定；有新袖长、裙摆、鞋口、帽檐时补真实形态、隐藏区与覆盖差异，不能仅换ID宣称适配。
3. 为准备发布的角色动作能力补齐映射；上衣增加一款不要求重画其他款，新增长裙也不要求改写通用人物渲染器。长裙的前后摆、长靴的裤脚、长发/帽子的收发用明确子层与组合变体表达。
4. 有新类别（例如围巾、外套）时在slot定义中增加稳定slot_id、所需锚点、可选/必选、占位冲突及层序约束。每姿态仍输出完整有序层列表，不能以追加一个全局z值解决所有动作。加载器拒绝未注册槽位、缺锚点和层序循环。
5. 验证新款涉及的接口及实际发布组合；新款单独好看不代表与全部旧款通配。所有已发布配方仍须有完整证据，扩充到任意组合前不能只抽查少数组合并宣称全部兼容。

新增体型沿用同一合同与工具，独立冻结比例、关节与运动视图，再适配衣物。无需复制一套引擎或分叉一套生成脚本；相同语义锚点名称不意味着成人与儿童可共用坐标或衣物像素。

### 当前可执行构建合同

统一构建入口为 `tools/characters/build.py`，新配方使用 `coastal-character-construction-v1`；字段与实际西锄示例见[工具说明](../../tools/characters/README.md)。`build`只产生不可覆盖的评审构建，`verify`重新解析配方和实际依赖并逐RGBA重建；`check.py`与PR/push工作流检查仓库入口和生产依赖。当前生产发布门禁仍关闭，不存在新active_release。

首版支持完整整帧分层、alpha-over与二值归属替换；源帧合成后的整帧注册须绑定确切记录并与模板variant一致。构建时裁剪/密度缩放、局部变换和未声明接口明确拒绝。此范围不等于本规范全部接口/运动/发布要求已实现；扩能力必须先扩统一合同及反例测试，不新增批次专用构建器。技术构建成功不产生新的用户认可或动态接触证据。

### 增量构建、回归与发布

依赖链为：体型/动作姿态＋部件视图＋mask/层序＋配方→烘焙帧→原生证据→唯一发布清单。artifact_digest按每个配方/动作的实际依赖闭包计算；发布清单另记录全局release哈希。只追加无关动作/衣物不使未受影响美术证据失效；改共享身体、姿态、mask或合成算法，则所有实际依赖它的结果必须失效并重建，不能靠旧文件名沿用证据。

motion_set新增action时保留其他action_id及其revision；修改pose/锚点接口时明确增加版本并迁移受影响映射，升级动作集总版本不等于所有动作都已重验。发布清单要核对旧证据的依赖哈希仍一致，不盲目继承通过状态。

扩展验收至少包括：增加不同于小样帧数的新动作能被遍历/播放；新增衣物不修改通用合成/播放代码；缺动作/视图明确拒绝；增加子层后前后关系正确；未受影响配方输出保持一致；修改共享依赖能正确失效关联证据；仅一个active_release且所有生产角色都能在其中解析；正式导出不含旧模型运行依赖。新玩法处理器另做业务测试，存档ID迁移另做保存/重载验证。

先实现所需基础合同，不预建完整编辑器、自动蒙皮、任意动作生成或跨体型自动适配系统。可扩展性减少重复工具开发与重复绘图，不能免除新姿态、新轮廓和动态混搭的美术工作。
