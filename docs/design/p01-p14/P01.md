状态：设计完成（本次交付）；不包含任何玩法代码。前置P00。实施消费者P02–P07必须遵循[共享合同](共享合同.md)。

## 交付与决定

本任务交付共享合同的A–G节、P02–P07任务卡，以及M2/M3前向接口。保留现有PlayerState、容器、SaveService和foraging兼容入口；采用“纯规则候选快照→校验→保存→整体发布”的单机事务，避免多个模块分别写盘。旧商品目录扩展，不重建库存系统。

## 存档迁移顺序

1. 原始JSON非Dictionary→拒绝。version非整值/不在支持集合→拒绝；高于当前版future=true并保护主文件，不能退回旧备份覆盖未来档。
2. v1/v2先按原有合法性完整校验，v1补location=harbor。保留位置、格子顺序、姓名、collected/discovered/total，不凭空补回已消费物品。
3. 新增default_life，version=3；迁移不直接写盘，继续游戏后通过正常保存提交。初始化采集点视为day1当日已采，day2刷新。
4. v3先校验v3；升到v4仅添加M2状态，升到v5仅添加人口状态。实现P02时只支持到v3；不能提前声称能识别v4/v5。
5. main坏档可尝试合法backup；失败不改任何原文件。write_save先校验当前版本完整快照，再按现有临时写入流程保存。

## 日结时序（源日d → 新日d+1）

在同一候选副本：检验expected_day==d且last_settled_day==d-1 → 作物使用源日watered增长并清浇水 → 清当日collected → 种子补货/收购额度 → M2按源日既有家庭和雇员结算 → M3每逢d%7==0评估迁入 → 写源日汇总日报 → day_id=d+1、last_settled_day=d → 记录sleep receipt → 校验保存 → 发布。

日报的day_id表示**刚结算的源日**，UI显示“第d日总结，今天第d+1日”。即时交易已发生，不在日结重复扣钱；日报仅汇总对应events。M2结算产生的收入成本可计入源日，但迁入新户eligible_from_day=d+1，不能参与源日消费工资。
