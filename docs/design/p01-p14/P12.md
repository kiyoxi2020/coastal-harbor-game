## 身份与日程

npc_catalog提供static get_npc(id:String)->Dictionary、static schedule(id:String, restaurant_status:String, phase:String)->Dictionary；返回目标marker_id、dialogue_key与visible。三个固定实例：

| npc_id / 显示称呼（开发名） | resident_id（P13用） | 职责/日程 |
|---|---|---|
| npc_cook / 餐馆老板 | hh_01_w1 | closed在餐馆外，trial/operating在服务窗口工作；晚间回街边集合点 |
| npc_neighbor / 邻居帮手 | hh_02_w1 | closed在旧屋外公共点，trial/operating在餐馆帮工；晚间集合点 |
| npc_market / 鱼摊摊主 | hh_03_w1 | 白天鱼摊服务点，晚间集合点；交易不依赖演员恰好到位 |

姓名为开发称呼，不锁定正式故事姓名。P12身份来自静态表，不计数人口；P13以resident_id连接唯一家庭成员，不能另加三人。

M1时间为手动日结，不发明24小时时钟。P12只增加**非存档的展示阶段**：进入当天/读取存档先phase=work，当前室外累计可操作实时时间180秒后phase=leisure；打开菜单、室内或过渡不累计，换日重新work。phase不改变营业、经济或迁入，重载可以从work开始；报告明确这是演示日程，不是完整昼夜系统。

在HarborExterior/NPCSchedulePoints放restaurant_work、restaurant_wait、market_work、neighbor_rest、evening_meet Marker，前两个随餐馆实例放并由导出NodePath引用，市场点随Market实例。每个NPC有稍微错开的站位，避免三个角色堆成一人。所有点需步行可达。

## 移动与交互

town_npc为CharacterBody2D，Sprite2D/AnimatedSprite2D、FeetCollision、NameLabel、InteractPoint在.tscn；速度30世界单位/秒、碰撞半径5，不能复制player.world造成输入同步。优先使用手工路点折线沿现有陆地移动，路径列表为Marker引用，不从屏幕截图坐标推断。

到目标<=3单位即停；连续2秒位移<1且目标未达，等待1秒后重新选择同一路径；连续2次受阻停在当前位置并标记blocked，不穿墙、不瞬移。目标重新改变后清blocked重试；再次进入区域时可在静态可达出生点加载，但不能在玩家可见移动过程中闪现。后台工作继续按状态结算。

E交谈打开dialogue页Surface/{Speaker,Body,Actions,Close}；台词优先级：blocked提示→餐馆closed困难→trial试营业→operating感谢→通用生活。npc_market提供“看看货物”转trade；npc_cook提供“供货/近况”转restaurant；npc_neighbor提示菜园/住宅，不直接给钱或修改人口。
