# P08：M2配方、经济与初始来源设计

状态：P07后设计校准完成（2026-10-20，设计基线2）；P09–P11仍待实现和正式验证。本轮只修改设计文档，未改变运行游戏的资金、配方或操作。依据P07自动/原生证据，无真人体验反馈；下述设计算术不是Godot经济测试。

## 目标与范围

用有限资金、有限库存、5个四人家庭验证餐馆自主经营。家庭按户每日购买1份“家庭餐”抽象，不声称每份等于一个人的全部营养。食物不足只记未满足需求，不死亡、不扣全部资产。主食分类、真实营养与动态物价延后，不靠隐藏谷物/捕鱼前置阻塞本轮。

## 商品与配方

新增catalog商品沿用共享合同E，max_stack99。配方统一配置文件scripts/simulation/recipe_catalog.gd，static get_recipe(id: String) -> Dictionary、static all_ids() -> Array[String]。

| recipe_id | 投入（每批） | 产出（每批） | 用途 |
|---|---|---|---|
| clam_salad | clam1 + lettuce1 | clam_salad2 | 玩家制作/家庭餐；餐馆零售价18G/份 |
| snail_stew | snail1 + tomato1 | snail_stew2 | 玩家制作/家庭餐；餐馆零售价26G/份 |
| marine_fertilizer | kelp2 | marine_fertilizer1 | 同一株最多一份待生效肥料；下一次有效浇水日额外+1增长 |

M2菜谱无加工时间，按操作或日结批次消耗；并非凭空生产。玩家制作不扣工资；餐馆批次受职工/工资/投入限制。菜谱产物不由市场直接收购，玩家可自存或向餐馆供货。餐馆收购玩家原料同市场卖出价，成品salad12G、stew18G；每品每日最多收4个；不收肥料或种子。

## 日结顺序（town_rules.settle源日d）

1. 对eligible_from_day<=d的每户按ID排序发外部生计收入12G：external_fund逐户支付min(12,剩余基金)，扣基金加家庭钱；记external_livelihood。基金耗尽则0，报告，不无限补钱。
2. 仅enabled餐馆预留工资：按employee_households顺序，最多2名（P13后最多3名），每名4G；现金够几名就雇几名，M2每户最多一名员工，与P10一致；P13改为具名岗位后按人去重。钱转到对应家庭，实际批次上限=已支付员工数，最高3。0员工则不生产，不新增欠薪负债。
3. 市场自动采购有限供给：目标clam/snail/lettuce/tomato库存各4，按该顺序补缺口，受depot.stock和market.cash限制，最多补至4；采购成本分别4/5/6/10G，支付市场→depot。每次实物搬移与转账记一次purchase事件。有限仓无自动刷新；种子补货仍用共享合同E明确external_restock。
4. enabled餐馆生产：先使用原料库存；每批优先clam_salad，其次snail_stew。尝试补买该批缺少原料（市场价8/12或10/20，双方现金/库存/容量足够才整批补齐），然后消耗原料产2餐；无法做salad再试stew，两者都不行就停止本日剩余批次，不扣未成功采购的钱。
5. 家庭消费：从consumption_cursor对排序后eligible家庭列表循环，每户最多1份；先买salad18再买stew26，现金不足可尝试更便宜的现有商品，无商品或付不起就记unmet。钱从家庭→餐馆，商品明确consume销毁，不放家庭永久仓。全部家庭轮询一次后cursor=(cursor+1)%户数，以轮换缺货承担者。closed餐馆不售，trial/operating均可售。
6. 基于真实paid_staff、产出、销量、缺料、利润更新last_metrics、food_history（最近7日）和daily_metrics（30日）；supply_quota刷新为4；状态转换见P11。利润=销售收入-采购额-工资（本原型现金口径，清楚标注，不称会计利润/增加值）。采购额含源日已成功supply的付费收货及本次市场采购，各记一次；注资本金排除。

restaurant.enabled=false时不支付工资、采购原料或售餐；市场采购和外部生计仍进行。P10先直接测试enabled=true夹具，P11再开放试营业按钮。工资已发但没原料可生产是合法成本，要在日报解释。餐馆内部采购不占玩家向市场卖货的buy_quota；仍受双方资金、现货和容量约束。

## 验收、防死锁与放行条件

玩家可提供原料/成品；餐馆正常后从市场采购维持，不要求每天玩家跑腿。depot有限240原料，足够验证14日但不承诺永续经营；耗尽需明确“区域供给不足”，不能无限生成库存。长期扩展补给属于M4之前评审事项。

P08复核用例（独立经济单元夹具，非默认新游戏）：将餐馆设enabled=true/status=trial，预置clam2、lettuce2、snail1、tomato1，市场仅有种子。首日2员工耗8G，库存足够做2批salad，得4餐并卖4户×18=72G，餐馆cash300-8+72=364；各户先+12，hh01/02另+4，4户各-18，未买到1户保留现金。初始cursor0→1；5户需求、满足4、满足率0.8。市场补货支付4×(4+5+6+10)=100G给depot（市场初始无四种货时）。全体资金总和不变。

P08设计完成门槛：配方不依赖未实现物品，账本能对平，P09/P10/P11使用同一字段和公式；P07后若校准需修改此表与全部用例，不只改代码。


## P07后校准结论（设计基线2）

### 方案比较与采用范围

| 方案 | 作用 | 取舍 |
|---|---|---|
| 保留有限需求，接入原定餐馆资金回流；增加玩家有来源的注资恢复（采用） | 家庭消费→餐馆→鱼摊/玩家；小规模经营可验证，倒闭有明确恢复操作 | 不承诺消化16格全部产量；需显示收购额度、资金与缺货原因 |
| 增加商户初始现金/每日补满 | 推迟或遮住P07现金耗尽 | 初始加钱不增加需求，每日补满破坏资金来源；不采用 |
| 立即加入外销/浮动价格/批量自动种植 | 可扩大需求或减少操作 | 超出M2最小范围、涉及M4贸易及新操作设计；本轮不采用 |

保留100G玩家、1000G市场、12个/品/日上限和现有配方价格。额度是最大收购量，不是保购合同。市场现金不足时继续拒收；餐馆购买市场原料可把家庭资金带回市场，但不购买海带、且优先salad不保证消耗海螺/番茄，故不能宣称所有物品都有持续销路。无需为通过验收强行种满、采满或卖满。

### 劳动量与首轮目标

P07默认两株仅用于519/581规则基线；16格首轮为16翻土+16播种+48浇水+16收获=96次农田动作，另有采集42、交易27、睡眠7。原生首日48次农田动作自动执行35.225秒，包含田内走位/动画，不含买种和睡眠路线，更不代表真人耗时。

M2默认开业引导仍只需1生菜+1蛤蜊，不要求全田或每日供货；后续可选2–4格起步，16格保留为自由容量/压力测试。未浇水暂停、成熟可留地，不添加强制劳动惩罚。两个菜谱的每批现金毛贡献分别为36-20-4=12G、52-30-4=18G（计一名员工工资，不是会计利润）。玩家加工供货相对直接卖原料每批多4G/6G；不能声称所有加工都大幅增值。

肥料消耗2海带，放弃12G潜在销售收入，还要制作/施用两步，只缩短有效生长期，不减少全田点击数。肥效生效后可在之后再次施用，不允许同一时刻堆叠；不做“一株终身只能一次”的隐藏规则。需要终身限制时必须另立字段与迁移。P09记录肥料是否值得使用，暂不把它作为劳动减负方案。

### 有来源的停业恢复：P10规则 / P11界面

新增拟定命令`fund_restaurant`，args恰为`{amount:int}`，1..1000整值。仅玩家wallet→restaurant.cash同额转账，不生成收入、贷款、物品、配额或good_day；closed/trial/operating均可注资。钱包不足返回insufficient_funds，参数错误按共享合同D；目标余额超校验上限返回invalid_state，整单不变。保存失败与重放沿用ActionService合同。场景入口要求餐馆可达、对应页面打开；纯规则无空间依赖。

事件为transfer，source=player、target=restaurant、cash=amount、items={}、reason=restaurant_funding。玩家日报记cash_out，企业经营cash_profit不计这笔注资（但现金余额增加）。不承诺投资收益，不提供自动回款或撤回。P11新增金额/合计/注资按钮和明确确认；与供货区区分，防止误当“出售获得金币”，遵循现有逐层返回与键盘焦点规则。

精确恢复夹具：玩家wallet100，bag有clam1/lettuce1，餐馆closed/cash0/库存空；注资28→玩家72/餐馆28；付费供货两原料20→玩家92/餐馆8；开业后当晚支付2人工资8，做1批salad得2餐并卖36→餐馆36。没有钱做第二批时，整批采购失败无半扣。一个弱日仍trial，不保证立即operating；补足缺料/资金后再按P11两个good_day规则评估。

若玩家也0G且商户0G、餐馆0G、没有可售存货，则当前范围不保证任意耗尽状态可恢复；不得隐藏赠钱。提供具体资金不足提示，列入P11边界测试。默认新游戏及P07满田终点不属于该状态（后者玩家1100G可注资）；M2的恢复承诺限于有可用资金/原料来源的停供，不声称经济永不失败。
