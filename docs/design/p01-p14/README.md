## 阅读与使用

1. 读仓库AGENTS.md、PROJECT_STATE.md、HANDOFF.md并查git status。
2. 读[共享合同](共享合同.md)，再读当前任务卡和它明确引用的前置任务卡。无须重复全文读取GDD。
3. 确认前置任务有通过证据；文件/接口和设计不一致时先定位差异，禁止靠猜测改名绕过。设计修改须同步本包合同与消费者。
4. 按单项任务卡执行：失败用例→最小实现→自动验证→需要的原生验收→进度记录。一次只做一张任务卡；不能只创建文件和空函数就勾完成。
5. 结束更新[总计划](../../开发计划.md)及状态/交接；不自动提交、推送、导出或启动下一任务。

优先级：用户当前指示及AGENTS约定 > 本包共享合同 > 当前任务卡 > GDD建议值 > 模型自行推断。发现合同与任务卡冲突必须修正文档后继续，不能静默任选一份。

## 执行记录格式

在当前任务卡末尾追加，不改写设计验收为“已通过”：

```text
执行日期 / 实际HEAD：
状态：进行中 / 待验证 / 完成 / 阻塞
变更文件：
自动验证：命令、PASS/FAIL数量、失败原因、日志路径
原生验证：步骤 / 预期 / 实际 / 结果；截图或录像路径
未验证与遗留：
设计偏离：原因、合同版本、受影响消费者
下一任务或剩余步骤：
```

证据文件在/private/tmp可能被清理，长期结论写入任务记录。截图只能证明对应画面，不证明长期经济正确。不能将模型自评、代码能解析或无窗口成功退出当作完整验收。
