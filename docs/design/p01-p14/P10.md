# P10：餐馆、市场与家庭消费

前置P09。目标是后台14日可对账模型；此任务只建立规则和供货接口，餐馆复业场景P11。

## 文件责任

新增scripts/simulation/town_rules.gd、tests/test_life_economy.gd（复用P07的tests/fixtures/life_save_v3.json）；修改state_schema、player_state/save_service支持v4，life_rules加supply，day_rules接town结算。已有v1/v2夹具不动。town字段/数值/顺序以P08为准；Schema新增validate_v4(data:Dictionary)->bool，migrate_v3(data:Dictionary)->Dictionary。

## 供货接口

supply args={account_id:"restaurant",item_id:String,amount:int}，数量1..99；只从玩家bag→餐馆slots，餐馆付钱→wallet，按P08供货价与每日额度。closed也可接受供货，钱/容量/原料不足全败。成品供货是货物转移，不额外增加产出。market与restaurant双向接口通过统一参与者适配器复用事务预检，禁止复制一套不同的扣钱逻辑。

restaurant.stock不是另一个Dictionary真相，唯一库存为slots；depot用stock是无槽位的有限抽象后台仓。生产使用配方目录；家庭消费销毁餐馆现货并转钱。场景卸载不能调用town.settle两次；仅sleep日结分发调用一次。

## 校验与报告

新增家庭总数/成员/预算合法性；employee_households必须存在于households，M2允许每户最多一名餐馆员工（P13改为具名岗位映射）。restaurant.status枚举closed/trial/operating，enabled与closed一致性由P11规则控制；P10纯经济测试夹具enabled=true/status=trial。初始迁移为enabledfalse/closed。

last_metrics固定字段：{day_id,paid_staff,batches,produced:Dictionary,sold:Dictionary,sales_cash,purchase_cash,wage_cash,cash_profit,households_served,households_total,unmet_households:Array[String],reasons:Array[String]}。cash_profit可负；所有cash余额不可负。每日指标只写一次，加载不结算。food_history元素{day_id,served,total}，不能用UI显示比率作为迁入条件源。
