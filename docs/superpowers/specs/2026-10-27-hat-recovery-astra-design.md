# 东向草帽恢复设计：先建立帽口，再处理可见性

日期：2026-10-27。独立诊断与方案：`gpt-6-astra`，high。状态：**设计待评审，修复未完成**。本次只新增此文档；没有生图、改素材、改 catalog、运行新版原生验收或扩充其他方向。

## 结论与范围

先做 `idle_east_0` 的一顶草帽，复用现有帽冠、帽带及可用帽檐；按**原始头部坐标**明确帽口，再判断现有像素能否组成该接口。足够则只修归属与可见性；不足则由 GPT 只补帽口接触带。不要再次以“生成一个看起来相似的戴帽人物，再用耳尖对齐”作为制作方法。

单姿态先通过裸头戴帽，再验证当前短发戴帽；之后才扩展到东向四个 run 姿态及同配方 idle。身体、脸手、衣物、运动、其他样例均冻结。范围不是四方向、80状态重做或生产迁移。

依据为[人物唯一规范](../../design/character-art-pipeline.md)第3–5节及第9节、PROJECT_STATE/HANDOFF 当前失败段。以下路径以 `art/design/character-motion/adult-standard-v1/headwear-sampling-v1/` 为根。

## 现有资源能救到什么程度

- 保留所有原始 GPT 源。现有帽冠编织纹理、海军蓝帽带、大部分近侧帽檐及外轮廓有复用价值；重新提取可以恢复被 mask 裁掉但原稿存在的帽边。
- 肤色细线、生成脸的黑边、透明污染不属于帽子。删除它们是否合法，取决于源归属；删除后是否贴合，是另一项检查。
- 某处原稿只有皮肤/透明，没有可用帽面时，mask、换层和整数偏移均不能补出帽面。v3 `(344,152)` 是确定反例。该源不适合作为当前固定头部的完整帽体，不继续调偏移或局部缩放。
- 现有 run 独帽源不能一概判为报废：需分别检查实际帽口缺失集合。当前资料也不足以证明五姿态仅靠重新分类即可恢复。

## 路径选择

| 路径 | 具体工作 | 代价和边界 |
|---|---|---|
| A：只回收现有像素 | 回到完整原稿，重新标定帽/皮肤归属、帽口和真实前后面；不沿用 v2 切线 | 最小改动；只在目标接口所需像素全部存在时成立。透明或皮肤缺口一旦出现即退出此路径，不以扩大 mask 顶替补图。 |
| **B：保留帽体，局部补帽口（推荐）** | 先做A的缺口审计；不足部分交GPT生成接触带/内缘，固定原坐标和旧帽主体，只采纳通过几何门禁的帽像素 | 把生成自由度限制在缺失接口，避免再生整身带来的头型漂移。需要人工精确归属及一张帽口导图；不是无条件保证生图成功。 |
| C：全新独立帽视图 | 在目标头型导图上生成完整帽体及所需近远帽面，重新标定所有边界 | 可改变错误的帽腔投影，但重画和风格漂移风险最高。B失败后不能自动不停转用C；须先确认缺的是何种视图，以及是否接受帽型/帽檐变化。 |

## 单姿态 pilot 的具体构造

### 1. 冻结目标和坐标，不从生成身体找位置

目标是 `run-east/references/idle_east_0-bare.png`，512×768；世界根、显示比例、像素密度均用现有 idle 合同。保留完整原 RGBA，禁止用生成图的脸、耳、头皮、手或衣服替换原身体。

制作输入为原图上半幅 `(0,0,512,512)` 的方形窗口；原图坐标与窗口坐标相同。如为模型准备2倍参考，必须整幅 nearest 变为1024×1024，并在元数据记录这一唯一密度变换。模型输出只允许与该窗口同纵横比、按已约定整幅密度归一回512×512；不按帽 bbox 自动缩放，不以生成耳点计算修复平移。最终帽层放回512×768全帧，`full_frame`、placement `(0,0)`、local_scale `(1,1)`。

原耳弓顶 `(231,282)`、实际眉区域约 `x296..339,y234..242` 用于识别原头及复查，不能替代帽口。诊断中的颜色辅助 bbox 不作为新的语义锚点。

### 2. 先画只用于检查的帽口导图

由原头轮廓标定一条近侧接触曲线，明确帽子在哪一圈接住头。建议 pilot 起始折线（源像素）：

`(145,276) → (180,266) → (232,250) → (296,230) → (340,216) → (376,208)`。

两端位于实际原头外轮廓：原像素分别为 `(5,3,2,253)` 与 `(2,1,1,245)`。这条折线是**本设计建议的戴法**，尚非用户认可或已完成美术；它按原后枕、耳上空间、眉上额头确定，不能称为从旧帽得到的已验证帽口。首先在原头上看它是否形成合理帽口，明确两端及曲线后冻结，不能为迁就某次输出悄悄改线。

导图另标：曲线上方应藏入帽腔的原头皮区域、帽冠必须包住的完整头弧、近侧帽唇、远侧帽底、保持可见的眉眼耳/面部。帽檐伸出头外的合理空气区域不属于接触缝，不能为了“无缝”把帽檐下面全填满。导图可由脚本画线作测量说明；这些线/填充不进入正式纹理。

与旧帽对齐比较后，将缺失帽面和混入旧脸的区域分别圈出。初始可编辑带为接触曲线两侧各12源像素及两个端点邻域；只有明确缺口超出此带才以具体区域扩展。帽冠、帽带和外侧帽檐保留旧 GPT 像素。若上头弧也缺帽面，记录为帽冠几何问题，不能扩大接触带掩饰。

### 3. 用现有生图能力补“帽接口”，不假装具备硬 mask

内置 imagegen 只有参考图路径和文字指令，没有可提交的编辑 mask。所谓“冻结原图”由后处理只采纳授权帽像素实现，**不能保证模型内部不改图**。

输入采用三类明确分工的参考：①固定坐标的原头窗口；②同坐标的旧帽与原头合成，标明它只提供材质/外形并存在缺陷；③独立诊断导图，标明帽口、不可露头皮区、要补的接触带。完整原身体可作附加身份参考。提示词明确：只完善这顶草帽的帽口厚度和内缘，使其适配图①原头；帽子其余外轮廓/帽带不改；不加入头发、皮肤、脸线、光晕或文字；保持画布布局和比例，输出同一窗口的穿戴参照。

这不是再次相信生成身体：输出先按固定窗口归一，叠回**原身体**检查。生成脸仅供排除归属；不拿它的新边界作接触基准，不找最佳拟合变换。若模型把帽体移位/改变视角，或接触带只能沿其新脸而不能沿目标线落位，直接拒绝。

只从合格源稿提取授权带内真实帽面，和保留的旧帽组成新帽部件。每个像素记录来源图、归一变换和 ownership；接合处必须存在双方真实帽面重叠，选单一来源，不把两个半透明边重复叠加。禁止程序补色、扩张颜色、复制伸长某条帽边或把生成皮肤染成草色。保留完整新源及未采用区域。

如果原源帽像素已经完整满足帽口，跳过此次生图。若精确提取后仍缺帽面，不能把皮肤/黑脸线算作帽面来让检查通过。

### 4. 分开保存三个问题

1. `source_ownership`：仅说明旧/新源中哪些像素是帽子；皮肤、眉、耳、生成头轮廓全部排除。真实帽沿黑边保留。对源图与提取图做逐段对照，不能只检 bbox。
2. `coverage`：目标头型帽腔实际覆盖的上头皮；在此 pilot 中原身体不擦除，必须由真实帽冠/近侧帽唇覆盖。该 mask 是验收目标，不是产生帽像素的操作。帽下收发单独指定为当前短发目标表面。
3. `occlusion`：只把确实在头后面的远侧帽底放到原身体之前；帽冠、近侧帽唇在原身体之后。近侧实体帽边必须连续，不能被远侧分类切去一半；不按暗色、整块右下角或每列最低点判断深度。

采用 `far_hat → original_body → compatible_under_hat_hair → crown_and_near_hat` 只是这张导图的候选排序，不是全方向通则。若只有一个前景帽层已表达该姿态所有可见帽面，就不强行拆层。前后 mask 的并集必须精确还原完整帽层，交集为0；这是完整性检查，另需人工验证分界位置正确。

先通过 `hat`。随后 `hair_hat` 仅隐藏帽腔内部、在实体帽冠后不可见的发丝；禁用列最大值算法。帽外刘海/鬓发/耳后发不应凭空消失。若原短发体积无法塞进此帽口，明确需要一张 GPT 帽下短发变体，不擦掉原头皮或任意削短头发来宣称兼容；此时停在单帽已通过、发帽未通过。

## pilot 的接受/拒绝条件

所有检查绑定实际源图、归一变换、目标原身体、三类 mask、合成工具和输出哈希。像素是否仍来自原头皮/旧轮廓由合成来源归属图判断，不以肤色RGB阈值推断；草色与肤色相近也不能改变归属。先对现有失败稿运行相关检查，确认至少能抓住已知缺陷，再检新稿；不可从新稿反推一张必通过的验收 mask。

| 项目 | 可度量门槛与目视要求 |
|---|---|
| 原角色不变 | 原裸头素材哈希不变；授权帽/短发可见区域外 RGBA 差异为0。零身体像素来自新源；零局部缩放/变形/校正平移。 |
| 不露原头皮 | 在预先圈定应入帽腔的原头区域，最终可见原皮肤/旧头外轮廓像素数为0。重点含整个上右头弧，必须抓住 v3 `(344,152)` 反例；不得通过裁原头来归零。软边保留原始 alpha，边缘带另看明暗背景。 |
| 接触无缝 | 目标近侧接触曲线相邻的帽面必须到位；无一条非预期透明通路穿过帽唇和头表面的接触带，无悬空断点。按预先标定的接触区域检查，不要求帽檐所有悬挑下方封闭。两端和整条接触线逐段放大复核。 |
| 无肤色残片/双脸缘 | 帽 ownership 与人工源图非帽归属区交集为0。显示出来的肤色必须能追溯到原身体，不能来自戴帽生成源。沿整个内缘查看，不能只测前额单点。 |
| 无帽轮廓损失 | 原源确认可用且声明冻结的外轮廓、帽冠/帽带像素逐RGBA不变；新提取层不出现原稿没有的直切、缺角或一像素断边。每段删掉的黑边必须能说明其真实归属。 |
| 遮挡正确 | 整条远近交界对照导图；无源脸竖线/重复边缘。保留合法的原额头轮廓与真实帽沿轮廓，不能以“黑线数为0”作错误目标。旧 `(350,228)` 探针仅作 run0 历史反例，不套到 idle 或未经确定的新帽口。 |
| 发帽兼容 | 帽腔以外应保留的刘海、鬓发及耳后发逐像素不变；无头发从实体帽冠穿出，接触线无一排皮肤夹层。做不到就声明需要帽下发型源。 |

视觉门禁需要同一输出在原生游戏世界原尺寸、现有2倍面板、明/暗背景的近景各看一次；保存一张包括原头、帽部件、合成及接触放大的板。记录源图尺寸、输出512×768、实际纹理显示比例及原生屏幕包围盒。放大图用于找边，不能代替正常尺度的整体戴法判断；原生正常尺度通过也不能掩盖来源污染。单姿态先让用户看到这一张明确标为候选的结果，不把离线示意称为最终修复。

## 通过后怎样扩展

只处理东向 `run_east_0..3` 和 matching idle。每帧先冻结各自原头的帽口、上头弧及近远关系。投影确实相同且多点/轮廓残差在1源像素内时，允许基于真实头部锚点作整数登记复用同 view；否则补对应帽视图，不用旋转、缩放或“眉上12px”替代。

保留四姿态原时序。逐帧用同样的接口门禁；仅重验发生变化的 `hat/hair_hat`，并确认 bare/hair/衣物及其他样例哈希保持。原生最小验证为五姿态明暗停帧、四run姿态连续十循环、动作中裸帽/发帽切换不重置相位、停步回匹配idle；捕获全部姿态及run→idle接续，检查接触线和帽体有无抖跳。没有具体风险时不重跑旧80状态全套，也不把本轮通过外推为其他方向兼容。

## 明确停止条件

1. 在第一张导图上就无法确定帽口或近远面，先提供该导图与两种具体戴法供判断；不让生成模型替用户决定头型/帽型的变化。
2. 同一局部补图方法至多两份被几何门禁拒绝的输出。第二份须针对第一份的明确失败坐标调整参考或提示；两份均不能在固定原坐标落位就停止，不搜索偏移/缩放“救活”。
3. 停止时交付缺失图面清单：例如“额前帽口到原头间缺6源像素宽的内缘”“上右头弧需要更宽帽冠”“现短发需要独立帽下变体”，附失败源与缺口坐标。下一决策是补准确的帽面视图/帽口导图，或由用户明确接受改变帽型；保持原身体的条件不自行放宽。
4. 源稿有帽但归属不清时停在提取审查；源稿没有帽面时停在美术缺失。逻辑测试通过不越过这两个门禁。

本设计给出了能被证伪的最小恢复路径，尚未证明现有生图工具能在该接口生成合格像素，也未证明当前短发能无补图兼容。最终是否解决，以固定原头上的新帽实际图像、对应原生检查和用户视觉反馈为准。
