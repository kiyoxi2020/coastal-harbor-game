# 人物统一构建入口与门禁

用户已确认上一轮五项门禁方案并要求执行。此实施采用统一严格配方与构建器；只写文档不能阻止误用，另写每批素材专用合成脚本会重新分叉管线，因此两者均不采用。

## 范围与数据流

统一入口 tools/characters/build.py。新配方使用明确的 construction-v1 合同，存于 art/characters/recipes/<recipe-id>/<revision>.json；既有无kind的迁移配方只作历史评审，不能通过新构建门禁。配方精确绑定唯一model、母版、动作集、动作/方向、实际variant、必需能力、部件定义及同pose完整注册层。所有文件引用均带SHA256、限定在语义目录且不允许符号链接/越界。

构建器按声明层序执行alpha-over或二值归属替换；不重新应用诊断occlusion，避免软alpha叠乘。部件接口为完整整帧；原源坐标分层可合成后整体注册，但须绑定确切记录，并与所选模板variant的source_box及whole_frame_translation一致，不支持裁剪/密度缩放。合法运动位移保留，部件本地挪缩及其他接口明确拒绝。ownership/coverage/occlusion独立记录并纳入哈希，缺隐藏身体的参考不宣称能任意换衣。动作帧数由模板实际姿态读取，不硬编码四帧。配方与模板的pose、时长、canvas/root/scale必须一致，必需动作集与实际clips必须完全一致。

输出只能是新建的库内build目录或/private/tmp/coastal-*测试目录；先完整校验，在独占新目录中写帧，最后发布manifest，存在目录拒绝覆盖。manifest绑定配方、实际依赖、构建器代码及输出哈希；verify重新解析依赖并逐像素重建核验，旧证据不能在共享输入变化后保持有效。构建结果始终是review-only，绝不因有PNG或旧认可字段而变成正式发布。正式发布仍须另完成完整动态、接触、原生及用户认可合同，本次不制造active_release或放行生产切换。

## 自动门禁

check.py统一检查严格配方与已构建结果、生产人物入口冻结清单、退役制作根重建、Godot活动旧路径及绕开当前入口的引用。冻结清单只描述当前合法运行/试玩依赖，更新需明确重新评审；自动扫描不声称能判断任意新脚本的语义。GitHub Actions对PR/push运行测试与门禁；仓库分支保护需服务端设置，本地代码不能替代它。AGENTS和README指定构建与检查命令。

## 验收

先建立失败测试：旧配方、未知字段/版本/model、越界/符号链接、缺能力/pose/view/mask/源、重复层/错误层序/缩放、SHA篡改、输出覆盖、证据过期与新增生产引用均被拒绝。真实西锄衣装四姿态+idle按原层重建逐RGBA相等；三帧新增动作合成fixture证明帧数可扩展。输出为开发评审，无新增用户认可、正式发布或美术修改。冻结迁移JSON不改写，既有GPU证据保持原范围。
