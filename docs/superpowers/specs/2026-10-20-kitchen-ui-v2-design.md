# 厨房UI v2：支持扩展菜谱的食谱浏览器

日期2026-10-20；状态：方案已批准并完成v2实现；2026-10-21反馈修正见下。用户否定v1厨房UI，要求支持后续更多食物。P09配方/事务规则与肥效已实现；本任务只改浏览与表现，不提前增加餐馆或新食物。

## 版式与美术

1280×720逻辑画布内使用约1120×632居中面板，正式数值在实现时按原生可读性微调。顶部是标题、料理/加工与关闭。内容左侧约52%为搜索、只看可制作和3列网格，正常视野约3行；右侧为固定详情。

网格条目统一图标、短名称与可制作/缺料状态，选中框与键盘焦点明确；不可只用颜色表达缺料。料理页当前仅两道真实菜谱，加工页当前仅海藻肥，不生成虚假已解锁菜谱或填充大量空槽。条目增多时滚动，选择自动滚入视野。缺料条目仍可查看材料。

右侧显示真实产物图标、名称、每批产量、原料图标与名称及“持有/本次需要”；缺少明确标缺几份。多材料用详情内部滚动，固定底部数量与制作按钮不被挤走。现有三产物使用本轮GPT图标，场景/背包/配方/工具栏保持同源；概念图中的重画食物仅为构图参考。

GPT生成无字背景、普通/选中卡片、正常/悬停/禁用按钮、输入框、滚动条素材；切分后接真实控件。文字/计数不烘焙进图片。控件贴图按实际最小尺寸设计，避免九宫格边距大于按钮半高。装饰留在外缘，原生检查标题、食材与按钮的安全区域。

## 交互与扩展

配方浏览与制作分层：方向键/WASD在网格选择；E从菜谱进入右侧操作，不直接扣料。Tab/Shift+Tab切换网格、详情操作、页签/筛选；Esc/B从操作返回原菜谱，再按关闭；右上角关闭直接关闭。搜索编辑期间字符输入不触发世界或WASD导航，Esc先退出输入回网格，保留查询。只有明确确认制作才走现有事务。

数量范围继续1..20，明确“批次”和“份数”区别，每批2份的料理制作3批显示产出6份。最大按钮按当前快照寻找1..20内可合法制作的最大批数，包含扣料腾格与输出容量，不只按材料整除。容量不一定随批次数单调，不用未经证明的二分假设。“只看可制作”指当前存在合法批次数；不可制作按钮禁用并说明缺料/容量原因。

条目按稳定recipe_id生成，选择/滚动位置不依赖固定下标。制作后刷新数量与状态；筛选导致当前条目消失时选邻近可见项，空结果显示空态并禁用制作。筛选或搜索不改变任何库存与钱包。

RecipeCatalog提供有序目录及展示分类cooking/processing（静态定义，不写入玩家存档），UI按目录生成可复用recipe_card.tscn实例，移除range(3)与三个配方按钮的硬编码。RecipeCard内部静态布局放场景，创建与绑定数据放脚本。新增正式内容需补配方、商品/schema许可及GPT同源图标，但不再改页面节点数/布局。未来未引入的解锁、厨具、品质、效果字段不提前建设。
