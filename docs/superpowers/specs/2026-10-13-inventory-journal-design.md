# 潮港旧屋：背包、个人手账与进度保存设计

日期：2026-10-13。状态：第一阶段已在v0.5.0实现并验证；第二、三阶段保持后续范围。开发拆分见[实施路线](../plans/2026-10-13-inventory-roadmap.md)，实际交付记录见[第一阶段结果](../plans/2026-10-13-journal-release-result.md)。下文基线是开发前状态，不代表最新试玩版。

## 1. 目标与基线

采用A方案：完整规划、分阶段实现。第一阶段闭环为“赶海拾取 → 整理背包 → 存入旧屋储物箱 → 退出重进，物品和世界状态一致”。个人页是生活资料页，不是战斗属性页。

基线为当前Godot 2D v0.4.4：三种海产、六个固定拾取点、数量型背包，无存档。保留1280×720内部渲染、2倍镜头、640×416地图、默认居中且面积约占可用桌面50%的窗口，以及已确认海盐像素风。本文不代表当前试玩包已具备新功能。

旧《赶海与背包设计.md》描述v0.4.0历史实现；本文实施后替代其中“无容量、重开重置、无存档”的规则，不覆盖原有通行、碰撞和拾取距离规则。

## 2. 阶段边界

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| 第一阶段 | 格子背包、旧屋储物箱、个人基础页、设置、标题页与单槽存档 | 拾取、整理、仓储、退出重进闭环通过验收 |
| 第二阶段 | 任务手账、交易与资金、实际可用物品及快捷栏 | 委托与交易读写同一库存，快捷栏不复制物品 |
| 第三阶段 | 地图、图鉴、关系、料理、生活技能、复兴记录 | 随对应玩法分别设计和上线，不先展示空页面 |

不在第一阶段实现重量、耐久、品质、食材腐败、随机刷新、日循环、联机、装备属性或换装。不得为了填个人页而添加虚假资金、体力、等级。

## 3. 背包规则

- 初始24格，6列×4行；普通材料每格99个，工具每格1个。容量数据允许未来扩容，但本阶段没有购买扩容入口。
- 物品定义包含稳定ID、名称、图标、分类、说明、堆叠上限、是否允许丢弃、可用行为。格子只保存物品ID与数量；空格数量为0，不存未知ID。
- 分类为全部、海产、作物与食材、材料、工具；分类是查看筛选，不创建独立库存、不改变槽位。任务物品使用独立任务记录，不占24格，不能丢弃或存箱；本阶段无任务物品内容。
- 拾取先补同类未满堆叠，再使用空格。容量不足时不领取当前世界物品，原物保留；满包但同类仍有余量时可以拾取。
- 保留当前每点1个的海产拾取规则。未来多数量拾取另行设计，不在本阶段默默采用部分领取。
- 支持查看详情、移动、交换、同类合并、拆分及整理。不同物品交换槽位；同类合并至99，余数留原格。拆分数量为1至原数量减1，需选择空目标格；取消不改变库存。
- 整理只作用于当前容器全部槽位：先合并同类，再按分类固定顺序、物品ID排序，空格排末尾；不跨背包和仓库，不重复计入采集记录。筛选状态下仍标注“整理全部”。
- 首阶段采用选中格子后选择操作的鼠标/键盘双通路；拖拽不是验收前提。所有动作必须无需拖拽即可完成。
- 详情显示图标、名称、分类、用途、当前堆叠数量。只有实现实际效果的物品才显示“使用”；现有三种海产不伪装成可食用物品。
- 丢弃为永久移除，不生成地面物品。先选择数量，再显示名称、数量与不可恢复提示；确认框默认取消。工具与任务物品禁止丢弃。

## 4. 旧屋储物箱

初始48格，6列×8行，箱内滚动查看；与24格背包并列操作。箱子作为旧屋附近独立交互点接入，不扩大地图、不改变旧屋碰撞；实现时必须验证可达与不遮挡通道。

存入/取出可选数量，允许部分转移；目标先补同类，再用空格。必须实际接收后才扣除来源，剩余留原容器并提示。转移不计作采集。

“存入同类”仅针对点击开始时箱内已有的物品种类，将背包中的这些种类依次转入；不把所有新种类自动存箱。按背包槽位顺序处理，满箱时其余物品保留。整理和一键操作均不得复制或吞掉物品。

## 5. 个人资料与手账

第一阶段手账只有背包、个人、设置三个分页，不显示未实现的灰色任务/地图/图鉴页签。个人页显示人物像素预览、姓名、居住地“临海旧屋”、累计采集数量、发现的海产种类。

新游戏填写姓名，默认“归乡人”；去除首尾空白，空输入回落默认值，最多12个字符，不接受换行和控制字符。首阶段不提供游戏中改名。预览使用当前角色，不承诺新立绘或换装系统。

累计采集仅在世界资源成功领取时增加，发现记录按物品ID去重；整理、转移、读档不增加，丢弃不减少。现有内容集齐后最多发现3种、累计采集6个，不靠读档刷记录。

美术遵循暖米白底、深海灰蓝文字、海蓝分页和克制的珊瑚色强调。文字必须清晰，选中状态同时有边框或形状提示，不能只靠颜色。具体像素布局、图标和对照预览在界面设计步骤评审，不在本文承诺新美术资产。

## 6. 输入、暂停与设置

| 状态 | 操作与结果 |
| --- | --- |
| 场景 | WASD/方向键移动；E拾取或查看；R回路口且保留物品 |
| 地点提示 | E继续或关闭；同次按键不得继续传给场景 |
| 手账 | B/Tab打开与关闭，重新打开回上次分页；方向键/鼠标选择，E确认焦点操作 |
| 储物箱 | 场景E打开，B/Tab关闭；按钮标注存入/取出方向 |
| 数量/确认子窗口 | B/Tab先取消子窗口，释放后再按才关闭父面板；E只操作明确焦点，危险确认默认取消 |

所有面板提供可点击返回/关闭按钮，不要求Esc。首阶段保留B/Tab的明确返回含义，E不作为无焦点时的万能关闭键。分页提供可聚焦按钮，键盘可完整访问。

同一时刻只有一个顶层交互界面，确认框可叠在其上。地点提示显示时B/Tab不另开手账；手账/仓储打开时屏蔽场景E和R。打开菜单、储物箱或确认框后暂停世界和角色输入，UI仍响应；恢复时要求释放触发键，不产生自动移动、拾取或重开窗口。

设置包含总音量、音乐、音效、窗口/全屏切换、操作说明、保存并返回标题、保存并退出。无音频内容时不能暗示已加入音乐；音量设置与后续音轨共用总线约定。设置单独保存，不被新游戏重置。全屏只作用于本次运行；每次冷启动仍采用用户已确认的居中半桌面普通窗口。

## 7. 标题页与进度保存

单存档槽。标题页有继续游戏、新游戏、设置、退出；无有效存档时继续按钮不可用并给出原因。已有进度时新游戏须二次确认，取消保留原进度；新进度首次成功落盘后才替换旧进度。

存档包含格式版本、玩家姓名、背包和箱子全部槽位、位置、已领取点ID、累计采集和发现记录。不存UI节点或显示文字。没有旧版持久存档需要迁移；首次升级使用新游戏，不声称可以恢复旧版本已退出的临时收获。

成功拾取、丢弃和仓储转移后自动保存完整一致快照；关闭手账时保存整理结果，保存并退出/返回标题时再保存一次。窗口关闭请求也经过保存退出路径。正在选择拆分目标或确认数量时不产生半完成存档。

采用临时文件写入、读回校验、替换正式文件的流程，保留上一份有效备份。写入由一个保存服务串行执行，防止较旧快照覆盖较新进度。拾取的库存变化、点ID和统计必须在同一快照内。

保存失败保留内存进度并明确提示“尚未保存”；不自动退出、不假报成功。退出失败提供重试、返回游戏及明确确认后的不保存退出。突然强制结束进程无法保证最后一次保存完成，不作绝对零丢失承诺。

读取先校验格式版本、容量、数量范围、物品ID、点ID和字段类型。主文件损坏时尝试有效备份并提示恢复；两份均无效时保留原文件，说明原因，不自动清空。未来格式版本不支持时拒绝覆盖，提示使用兼容版本。非法位置恢复到已知安全出生点并提示，不把角色放入海里。

## 8. 模块职责与数据流

| 模块 | 职责与边界 |
| --- | --- |
| 物品目录 | 提供ID对应定义；不持有库存 |
| 容器规则 | 背包/箱子共享校验、堆叠、移动、拆分和转移规则；返回实际数量及失败原因 |
| 玩家/世界状态 | 个人资料、统计和已领取点；成功采集一次更新，不从HUD文字反推 |
| 交互协调 | 按状态路由输入、管理暂停与焦点；执行一次完整操作后通知界面和存档 |
| 保存服务 | 完整快照、校验、版本、备份与错误反馈；不操作UI格子 |
| 视图 | 订阅数据变更，展示并发出请求；不能自行直接增减物品 |

数据流：输入请求 → 校验 → 一次更新相关内存状态 → 通知视图 → 保存完整快照。请求失败时不改变来源、世界资源和统计。逐步替换现有foraging_state计数实现，保留现有拾取目标与碰撞逻辑；不保留两套并行库存作为真值来源。

## 9. 验收标准

1. 堆叠：98+1到99；已有99时进入空格；全满且无余量时拾取失败、世界物品保留。
2. 数量守恒：移动、交换、拆分、合并、整理和双向转移前后总量相等；丢弃只减少确认数量；非法数量/ID不改变任何状态。
3. 仓储：部分容量只转移可接收数量；一键存同类不引入点击前不存在的种类。
4. 统计：采集成功计一次；重复点ID、失败拾取、仓储、整理、读档不重复增加。
5. 输入：长按E不连领；关闭提示不拾取；菜单中E/R不操作世界；取消确认不执行破坏动作；鼠标和纯键盘都能完成主要流程。
6. 保存：重开恢复槽位、数量、姓名、位置和世界点；无存档、损坏主档/有效备份、两份均损坏、未知版本、写入失败均有明确处理。
7. 游戏回归：原沙滩通路、海面阻挡、树木遮挡、镜头限位及E查看不退化；R不清空收获。
8. 实机验收：在半桌面普通窗口、手动调整窗口及全屏下检查中文、长名称、空格/满格、焦点、滚动和提示遮挡；CLI测试不能替代此步骤。
9. 原六个资源点只够基础流程，容量/工具保护等边界由专用测试夹具提供，不往正式地图塞满测试资源。
10. 发布：完成后才更新2D最新版试玩包及源码，归档旧包且Git忽略；3D不变。设计稿更新不冒充功能发布。
