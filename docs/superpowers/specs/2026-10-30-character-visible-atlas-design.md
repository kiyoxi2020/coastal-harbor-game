## 已确定的方向

- 每个体型、部件款式、动作使用一张透明 RGBA 图集。
- 每张图按方向分行、动画帧分列。统一方向顺序为 north、west、south、east；同一动作的所有部件使用完全相同的帧格、帧数和坐标。
- 每个部位只有一个层，不区分前层、后层，也不在图内另设前后分区。
- 部件图保存当前姿态和适配范围内需要显示的像素。被身体遮挡的衣物、头发区域在制作时处理成透明。

## 一个公共布局与一个人物选择文件

公共 layout 定义体型、各动作的格子尺寸、方向顺序、有效帧数、帧时长、循环方式、根锚点、显示比例及必要动作事件。不同动作可使用不同格子尺寸，但同一动作的身体和所有部件必须一致。只支持统一帧格，不引入逐部件偏移。

人物 outfit 仅选择 layout、body、top、pants、shoes、hair、hat，以及确有需要的适配版本。无帽等可选槽位可以为空；缺失所需动作或适配版本报错，不用其他动作替代。

初始固定叠加顺序：body → shoes → pants → top → hair → hat。该顺序是制作合同：例如鞋可能覆盖裤脚的组合需制作相应裤子适配，而非逐帧改层序。

## 制作方式先对比，再选择

图集与合成方式已经确定，imagegen 的部件制作方式尚未确定。透明输出能力不等于精确贴合既有人体的能力；不预先承诺一次生成即可使用，也不把“生成完整部件再提取”设为强制流程。

完整裸身体验收归档后，从归档中选同一个实际人体姿态、同一件上衣做 A/B 小样，选择手经过胸前的姿态以覆盖遮挡难点。两种方式使用同一母版、画布、款式参考和质量标准：

| 方式 | 步骤 | 重点观察 |
|---|---|---|
| A：直接透明部件 | 提供人体与款式参考，请 imagegen 仅输出同坐标可见上衣，检查并修整 | 肩、领口、袖口是否对齐，是否混入皮肤，透明缺口是否正确 |
| B：穿戴效果后提取 | 让 imagegen 基于同姿态人体编辑穿戴效果，再提取上衣可见区域 | 身体、脸手、姿态是否漂移，提取是否干净，额外操作是否值得 |

B 不使用简单像素相减代替部件提取；生成过程的边缘或人体变化可能造成误提取。完整独立部件生成后提取保留为复杂款式的备选，不提前追加第三组批量实验。

记录每种方式的实际生成次数、修整步骤、人工操作时间、等待时间，以及原尺寸叠加后的对齐、透明边缘、遮挡缺口和身体身份变化。先判断质量是否合格，再比较总制作成本；不能用最快但不合格的样本获胜。相同问题连续两次未改善时停止同思路重试，分析原因。

单帧对比通过后，用暂选方式补同一单侧行走的连续姿态，检查款式一致性与动画接缝。只有连续小样也通过，才在文档记录最终默认方式、证据及适用范围，再扩展四向六动作；若两种方式均不合格，保留未通过结论，不启动批量生产。上衣的结果不直接推断成头发、帽子等所有类别的成功率，必要时为新类别做最小代表样本。

## 两种方式共用的交付流程

1. 优先检查旧资源能否复用，只对缺失或不合格像素使用 imagegen 制作，保留实际使用的原图和提示词。
2. 以实际姿态身体为参照制作或提取可见部件。选择、提取操作限于制作阶段，不成为运行或构建时的独立 mask 输入。
3. 最终保存透明 RGBA，直接包含正确 alpha 和软边，不混入其他部位的皮肤、脸线或手。
4. 由脚本将合格帧装入公共布局，不依赖 imagegen 精准排版；禁止粘贴其他人物脸手或任意缩放修补错位。
5. 检查原尺寸叠加与连续播放。相同姿态形态可复用图像，但不得为复用强行移动或缩放部件。

例如手横过胸前：上衣图中被手遮住的区域预先透明，叠到完整身体后显露底图的手。上衣图无需复制手，也无需运行时遮挡 mask。身体底图必须使用已确认的中性连体底衣版本，后续服装必须覆盖相应底衣；原穿衣底图不能直接作为本轮底图。

## 可见区域的适用范围

按身体当前姿态裁去的区域可在相同体型与姿态下复用。被特定帽子或其他服装遮住的区域不一定能跨组合复用。

默认头发用于无帽；如帽子直接覆盖就能获得正确外观，可复用默认头发；如戴帽需要收发或改变轮廓，使用明确的帽下版本。不得把已经裁去帽下区域的头发当作无帽完整头发。裤脚、靴子、衣摆交叉同理。只为实际需要的组合增加适配，不穷举衣柜。

不创建隐藏的逐帧 mask 或层序规则来弥补不兼容；不能成立的组合明确不支持。

## 构建与加载

构建器读取 outfit 和公共 layout，检查尺寸与动作覆盖，按固定顺序对整个动作图集做 alpha-over，输出每动作一张完整人物 PNG。manifest 只记录实际选中资源、layout、outfit、构建器版本及输出哈希，供复现和失效检查，不递归依赖历史配方、验收素材或旧 build。

Godot 读取同一 layout 和合成结果，按动作、方向、帧号取格播放；保持统一播放入口，不增加第二套长期播放器。

## 尺寸与验收

先核算每动作图集的原始尺寸与解码内存，并用目标 Godot 环境验证导入和渲染。不得为压小图集擅自缩小原图；若仍过大，在实施前讨论进一步按方向拆图。

先完成全动作四向裸身体并验收归档，再完成单侧行走部件小样：使用归档身体、两种袖长上衣、裤鞋，以及无帽/有帽头发。验证裸身与单槽替换、可见区域和连续动作后，再扩四向六动作。自动检查尺寸、有效帧、缺资源和可复现输出；原生检查前后遮挡、接缝、动作切换和实际显示质量。加载成功不替代视觉或严格运动验收。

## 已生成资源的处置

本次不删除、覆盖或批量重新生成旧资源。实施前按实际文件引用建立轻量迁移表，记录旧路径/哈希、新路径/哈希、处置类型与原因；不复制一整套旧库作为新的常驻备份。

| 现有资源 | 处理方式 |
|---|---|
| 选定人物母版、GPT 原图、提示词、必要来源信息 | 保留为身份与制作来源，不因换存储格式重新生成 |
| 已有衣裤鞋、头发和帽子纹理 | 优先原像素复用；旧 mask 和层序可用于一次性提取或合并，输出单层透明部件。检查是否混入身体像素、是否适配新身体及固定层序；不合格部分才修补或重做 |
| `body-views` 穿衣底图 | 保留作同身份姿态参考，不能直接改名为裸身。衣物下未绘制的身体无法通过抠图恢复，需要同母版补画并验收 |
| 现有 84 帧完整人物 build | 保留为迁移期间的外观、动作及时序对照和现有试玩入口；不是新部件的默认源图，不默认从成品反拆所有部件 |
| 动作时序、方向、锚点与必要事件 | 提取仍适用的数据写入公共 layout；画布变化时同步验证整帧注册与显示效果，不照抄失效坐标 |
| 旧 mask、逐帧配方、标注和构建中间件 | 新版构建不依赖。旧入口仍在使用时保留；依赖替换和验收完成后，检查引用再退出活动目录 |
| 历史截图、视频和重复展示资料 | 延续已授权精简策略，不恢复此前删除的大型材料；此次小样只保留必要输入、对比结果和简短决定 |

单层导出不一定等于把现有同部位的前后层直接合并：原先穿插在身体前后的像素必须针对当前姿态重新确定最终可见范围。旧部件只有在新身体和组合上验证通过，才标记为已复用。

迁移顺序：只读盘点 → 全动作四向裸身体制作、验收与归档 → A/B 小样 → 局部导出与连续验收 → 完整动作适配 → 切换现行入口及受控生产验收 → 清理失去依赖的旧活动资源。清理前确认旧文件可从 Git 或受控来源恢复；未进入历史的唯一原图不得删除。保留被采用的源图及最小追溯信息，退出的是旧运行/构建链，不是抹去来源。

旧构建通过或旧用户认可不自动继承给新身体、新 alpha 或新组合。没有变化的来源可复用，改变后的可见效果与动作范围需要重新验证。
