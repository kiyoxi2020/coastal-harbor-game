# 动态发帽候选：harvest-north

提供四个既有动作姿态及对应 idle 的 bare / hair / hat / hair_hat。bare 逐文件复制原衣装候选，脸、手、衣物及工具在实际发帽所有权以外逐 RGBA 保留。仅本目录声明的五个姿态得到适配；未登记用户认可，也未外推其他方向或款式。

新增运动发帽由内置 GPT imagegen 生成，提示词在 prompts，完整透明原稿在 sources。原稿为 1774×887，整张图统一 nearest 注册到 3072×1536；四列两行每格 768×768，不单独缩放部件。四个运动姿态各有经源图逐格目视审核的发型轮廓/刘海语义多边形（hair-semantics.json，768×768 源格坐标）。多边形从旧候选轮廓起草并以 GPT 源图核对，明确避开眉眼、耳、脸、颈和衣物；builder 只在授权区域内用原图 alpha/颜色辅助挑选发色像素，不再以最大连通域决定归属。帽檐轮廓在 builder 明确登记。每个运动姿态使用对应新视图，以当前姿态真实耳缘锚点做整数平移。全部源图与单格原稿均保留在整张原稿中。

对应 idle 使用既有 GPT 静态发帽原稿，仅在实际相同头部投影下复用：南向头锚点从 (230,245) 到 (256,244)，北向从 (282,245) 到 (256,245)。不缩放旧脸手，也不把旧身体合入输出。所有权 mask 和原稿已复制进 references。

层序为原同姿态帧→发型（发帽状态先收入帽内容积）→帽子。完整发型仍保留，帽下收发只写入派生图；当前五姿态手和工具均不与帽顶/刘海相交。ownership.json 分开记录源归属、头部注册、目标帧可见 alpha 叠绘和帽内容积；sample.json 绑定本地资源与父版 sample/五张实际 bare 输入的 SHA。

运行 `python3 build_sample.py` 可重建。validation.json 记录20状态的画布、同姿态非编辑 RGBA、原图字节哈希和重建检查。native-scale-contact.png 仅作 nearest 原显示尺度接触表，不能替代主代理的 Godot 原生停帧与连续播放。

源稿尺寸 1774×887；运动输出 1536×1920，display_scale=0.118556701，整帧原生显示约182×228；idle 输出512×768，display_scale=0.237113402，整帧原生显示约121×182。文字/UI不属于此资源。当前只完成美术登记和确定性结构/像素检查，原生验证和用户视觉认可交由主任务登记。

source-local-ownership 为 GPT 源单格坐标；source-ownership 是该归属随登记变换后的目标整帧副本。visible-coverage 从实际合成层 alpha 单独计算，处于当前 pose 整帧坐标；hair-under-hat-visible-coverage 则对应帽下收发派生层。coverage 只描述对同姿态烘焙头部的可见叠绘，没有目标身体擦除 mask；hat-cap-volume 是目标帧中只作用于已注册发层的遮挡规则。完整 GPT 原稿与单格视图未覆盖，帽下收发只写入派生层。
