## 来源与构造

三件分别用GPT内置imagegen在同一母版上编辑，不从上一件的生成图继续绘制人体。每件保留原图及提示词：

| 部件 | GPT穿戴源图 | 提示词 |
|---|---|---|
| 上衣 | [top-worn.png](top-worn.png) | [top-prompt.txt](top-prompt.txt) |
| 长裤 | [pants-worn.png](pants-worn.png) | [pants-prompt.txt](pants-prompt.txt) |
| 皮鞋 | [shoes-worn.png](shoes-worn.png) | [shoes-prompt.txt](shoes-prompt.txt) |

[语义遮罩](semantic-masks.json)逐方向定义衣物边缘、手掌和脖颈保护区、旧裸脚与新鞋的真实覆盖体积。[构造脚本](build_clothing_proof.py)只做原位提取/透明遮罩/合成，不绘制人体，不移动或缩放部件。颜色范围仅在人工限定区域辅助区分蓝布、皮肤与原内搭；不用暗色连通块全局判定器官。

图层顺序为裤→上衣→鞋→发→帽。衣物按语义归属替换像素，不重复alpha描黑。鞋层不带裸踝皮肤，防止皮肤覆盖裤脚；更换鞋时也清除其覆盖体积内的原裸脚轮廓。旧领口布料不归脖颈皮肤；手掌和裸露五官始终来自当前母版。

parts目录保留12张衣裤鞋透明层及其owner遮罩；proof目录保留8种衣裤鞋状态×4方向＝32帧，另有全套＋头发/草帽8帧，共40帧。40是组合帧数，不是40个设计。所有画布512×768，部件变换恒为identity，兼容范围仅adult-standard-v1站立。

## 验证与后续

逐像素检查非组件归属区域RGBA、完整头部和手掌；原生检查40帧的明暗背景及12处接口局部，并让同一预览Sprite2D实际切换32次。原生脚本[render_review.gd](render_review.gd)直接加载本目录proof；不启动玩法、不加载玩家存档，也不是正式运行时衣柜。manifest.json绑定源图、母版选择、遮罩、脚本、部件与输出，review.json将当前版本与原生证据绑定；旧中途截图不作验收。

这是第一套拟合及与原装的有限替换验证。原装乳白上衣/灰短裤仍内置于母版，不算第二套独立组件；隐藏身体尚未补齐，不宣称支持任意短袖、拖鞋或新露肤区域。用户确认本套贴合后，再做第二套衣裤鞋并逐槽交叉验证，之后才扩体型/款数。正式角色、女性/老人/儿童、动画、P12及提交/推送/导出均未推进。统一规范见[人体管线](../../../docs/design/character-art-pipeline.md)。
